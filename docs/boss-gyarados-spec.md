# 갸라도스 보스 구현 명세

> 대상: `F3Room7_Boss`의 `Boss_Gyarados` — 3층 최종 보스  
> 현재 구현: `Assets/Game/Scripts/Combat/Bosses/GyaradosBossController.cs`
> 기준 단위: Unity 월드 단위. 타일 1칸과 플레이어 폭은 각각 약 `1 unit`이다.  
> 상태: 하이드로펌프 2차 개편(벽 반사) 구현 완료

## 0. 핵심 요구사항

갸라도스는 전투장 안팎을 오가며 **공격 가능 시간과 생존 시간이 교대로 오는 최종 보스**다.
단순히 체력과 피해가 높은 보스가 아니라, 상시 해류·고정 장애물·제한된 공격 기회가 서로 영향을
주어 어렵게 만든다.

- 전투 내내 위·가운데·아래의 **삼중 해류**가 작동한다.
- 갸라도스에게 피해를 줄 수 없는 `잠항` 상태와 피해를 줄 수 있는 `노출` 상태가 교대한다.
- 잠항 상태 패턴은 `반사 하이드로펌프`, `격류 압착` 2종이다.
- 노출 상태 패턴은 `잉어킹 소환`, `똬리치기` 2종이다.
- 체력 50%에서 2페이즈로 전환하며 새로운 패턴을 추가하지 않고 같은 규칙을 강화한다.
- 잠항 상태는 시간으로 끝내지 않고 **사용한 패턴 수**로 끝낸다.
- 노출 상태는 받은 피해량이 아니라 **고정된 시간**으로 끝낸다. 강한 빌드는 같은 시간에 더 많은
  피해를 줄 수 있어야 한다.
- 삼중 해류와 남아 있는 잉어킹 외에 서로 다른 직접 공격을 동시에 실행하지 않는다.
- 모든 밸런스 수치는 `Inspector`에서 조정할 수 있어야 한다.

### 0.1 이번 2차 개편의 범위

1차 구현을 플레이한 결과 갸라도스가 맵 바깥으로 잠항하고 다시 등장하는 연출이 어색하지 않게
완성되었다. 따라서 외곽 바다와 진입·이탈 구조를 그대로 사용하면서, 하이드로펌프만 다음과 같이
변경한다.

```text
현재: 위·아래에서 발사 → 수로 경계에서 해류 방향으로 1~2회 굴절
변경: 네 방향에서 발사 → 전투장 벽에서 입사각과 같은 각도로 1~2회 반사
```

이번 작업은 처음부터 보스를 다시 구현하는 작업이 아니다.

- `Intro → Exposed → Exit → Submerged → Enter` 상태 기계를 유지한다.
- 삼중 해류, 격류 압착, 잉어킹 소환, 똬리치기를 유지한다.
- 외곽 깊은 바다, 잠항 마커, 진입·이탈 연출을 유지한다.
- `GyaradosHydroBeam`의 남는 물줄기, 피해 판정과 물보라 연출을 재사용한다.
  (진행형 선두는 이후 즉발 발사로 교체됐다 — 5.1·5.5절 참고.)
- 수로 경계 굴절 계산과 하이드로펌프용 해류 방향 잠금만 제거한다.
- 하이드로펌프와 무관한 밸런스·프리팹·다른 층 콘텐츠는 수정하지 않는다.

## 1. 현재 구현 기준선

현재 `F3Room7_Boss`에는 갸라도스 1차 보스전이 구현되어 있다.

- 보스방 안쪽 크기: 약 `14 × 10`
- 권장 전투 계산 영역: 반너비 `6.2` × 반높이 `4.2`
- 갸라도스 최대 체력: `900`
- `EnemyController.basicAIEnabled = false`
- 갸라도스 스프라이트 동작: `Idle`, `Walk`
- 잉어킹 전투용 스프라이트: `Assets/Game/Art/Characters/Magikarp/Sprites/Hop.png`
- 플레이어 이동 속도: `5`
- 플레이어 공격 중 이동 배율: `0.5`
- 이상해꽃 기본 공격력: 근거리 `25`, 원거리 `17`이며 유물과 기술 강화로 더 높아질 수 있다.
- 플레이어 피격 후 무적 시간: `0.5초`

현재 구현 파일과 책임은 다음과 같다.

| 파일 | 현재 책임 | 이번 작업 |
| --- | --- | --- |
| `GyaradosBossController.cs` | 상태 기계, 패턴 선택, 굴절 경로 계획 | 하이드로펌프 경로 계획만 반사 방식으로 교체 |

1차 구현의 굴절 방식에 종속된 값이다. 아래 5절과 12절에 따라 최소 범위로 교체한다.

## 2. 보스 정체성과 기존 보스와의 구분

| 보스 | 핵심 판단 |
| --- | --- |
| 버터플 | 투사체 방향, 지나간 자리에 남는 장판, 회전하는 안전 부채꼴 |
| 코뿌리 | 방 전체 낙하 지점, 근거리 찌르기, 연속 돌진 |
| 갸라도스 | 흐르는 바닥, 벽에서 반사되는 공격 경로, 고정 장애물, 제한된 공격 가능 시간 |

갸라도스에서 다음 형태를 주력으로 사용하지 않는다.

- 작은 탄을 다수 뿌리는 탄막
- 무작위 위치에 비나 물기둥을 떨어뜨리는 스톤샤워형 공격
- 플레이어를 향해 방 끝까지 몸으로 돌진하는 이판사판형 공격
- 플레이어의 지나간 자리를 연속 장판으로 기록하는 공격

### 2.1 전용 보스맵 구조

`F3Room7_Boss`는 다른 보스방의 바닥과 벽만 바꾼 일반 직사각형 방으로 두지 않는다. 갸라도스의
잠항·등장과 삼중 해류를 시각적으로 설명하는 **전용 바다 경기장**으로 개조한다.

```text
~~~~~~~~~~~~~~ 외곽 깊은 바다 ~~~~~~~~~~~~~~
~                                             ~
~   ┌──────── 플레이 영역 ────────┐    ~
~   │ 위쪽 얕은 수로      ← 또는 → │    ~
~   │ 가운데 얕은 수로    ← 또는 → │    ~
~   │ 아래쪽 얕은 수로    ← 또는 → │    ~
~   └────────────────────────┘    ~
~                                             ~
~~~~~~~~~~~~~~ 외곽 깊은 바다 ~~~~~~~~~~~~~~
```

#### 플레이 영역

- 중앙 플레이 영역은 현재와 같은 약 `14 × 10`을 유지한다.
- 중앙은 밝은 얕은 물 또는 모래·암초 지면으로 표현한다.
- 위·가운데·아래 수로의 경계는 서로 다른 바닥을 새로 만들지 않고 옅은 거품선과 동적 화살표로
  구분한다.
- 플레이어, 잉어킹, 범람, 똬리치기의 판정은 중앙 플레이 영역만 사용한다.
- 현재 `Sea.png`의 모래·암초·얕은 물 타일을 재조합한다. 이 명세를 위해 별도의 수문이나 구조물
  스프라이트를 구하거나 제작하지 않는다.

#### 외곽 깊은 바다

- 중앙 플레이 영역 바깥에는 최소 `2 unit` 폭의 진한 깊은 바다 띠를 둔다.
- 외곽 바다는 갸라도스가 잠항하고 공격 출발 위치를 보여 주는 연출 공간이지 플레이 공간이 아니다.
- 플레이어가 외곽 바다로 나가지 못하도록 중앙 경계에 충돌체를 둔다.
- 갸라도스의 물결·그림자·눈빛과 하이드로펌프 발사 원점이 카메라 안에 보이도록 카메라 범위를
  조정한다. 중앙 플레이 영역의 실제 크기는 늘리지 않는다.
- 갸라도스는 외곽 바다에서 벽에 숨는 것이 아니라 물속에 잠긴다. 잠항 중 본체는 옅은 그림자나
  물결로만 표시할 수 있다.

#### 맵 기준점

좌표를 보스 코드에 직접 작성하지 말고 `F3Room7_Boss`에 다음 기준점을 배치해 참조한다.

| 기준점 | 용도 |
| --- | --- |
| `ArenaBounds` | 중앙 플레이 영역, 수로 경계와 범람 크기 계산 |
| `HydroReflectBounds` | 하이드로펌프가 반사되는 네 벽의 안쪽 면 |
| `ExposedAnchor` | 노출 상태에서 갸라도스가 머무는 중앙 위치 |
| `DiveAnchor_Top/Bottom/Left/Right` | 외곽 바다의 잠항 연출 위치 |
| `HydroOrigin_Top/Bottom/Left/Right` | 하이드로펌프가 중앙으로 들어오는 네 방향 발사 원점 |
| `CurrentLane_Top/Middle/Bottom` | 세 수로의 표시와 해류 판정 범위 |

기존 `HydroOrigin_Top/Bottom`은 유지하고 같은 규칙으로 `HydroOrigin_Left/Right`를 추가한다. 새 기준점이
비어 있으면 `HydroReflectBounds` 또는 `ArenaBounds`의 해당 면 바깥으로 자동 계산하는 예비 처리를 둔다.

`HydroReflectBounds`는 시각적으로 물대포가 부딪히는 벽의 안쪽 면과 일치해야 한다. 기존
`ArenaBounds`가 그 면과 일치하면 같은 트랜스폼을 참조해도 된다. 둘이 다르면 반사 계산에
`ArenaBounds`를 억지로 사용하지 말고 별도 기준점을 배치한다. 물대포가 벽에 닿기 전 허공에서
꺾이는 것이 보이면 안 된다.

## 3. 전체 상태 기계

### 3.1 상태 목록

```text
Intro
→ Exposed(노출, 피해 가능)
→ Exit(이탈 전환, 무적)
→ Submerged(잠항, 무적)
→ Enter(진입 전환, 무적)
→ Exposed
→ 반복
```

전투는 `노출` 상태로 시작한다. 처음부터 긴 무적 구간을 보여 주지 않고, 플레이어가 갸라도스를
공격할 수 있다는 사실부터 학습하게 한다.

| 상태 | 피격 가능 | 보스 충돌 | 사용하는 패턴 |
| --- | --- | --- | --- |
| `Intro` | 아니오 | 아니오 | 없음 |
| `Exposed` | 예 | 예 | 잉어킹 소환, 똬리치기 |
| `Exit` | 아니오 | 아니오 | 없음 |
| `Submerged` | 아니오 | 아니오 | 반사 하이드로펌프, 격류 압착 |
| `Enter` | 아니오 | 아니오 | 없음 |

### 3.2 첫 진입

- 갸라도스는 전투장 중앙의 노출 위치에서 시작한다. 권장 시작점은 `(0, 0)`이다.
- `0.8초` 동안 포효와 물결을 보여 준다.
- 이 시간에는 갸라도스와 플레이어 모두 정상적으로 움직일 수 있지만 보스만 무적이다.
- 연출이 끝나면 첫 `Exposed` 상태를 시작한다.
- 삼중 해류는 `Intro`가 끝나는 순간부터 작동한다.

### 3.3 노출 상태

| 항목 | 1페이즈 | 2페이즈 |
| --- | ---: | ---: |
| 기본 노출 시간 | `6.5초` | `5.0초` |
| 내부 패턴 사이 대기 | `0.22초` | `0.14초` |

- 노출 시간은 갸라도스가 공격 가능해진 순간부터 흐른다.
- 노출 시간이 끝나도 실행 중인 패턴을 강제로 끊지 않는다.
- 시간이 끝나면 새 패턴을 선택하지 않고, 실행 중인 패턴의 판정과 후딜이 끝난 뒤 이탈한다.
- 받은 피해량 때문에 조기에 이탈하지 않는다.
- 갸라도스가 사망하면 시간을 무시하고 즉시 전투 종료 처리를 시작한다.

### 3.4 잠항 상태

| 항목 | 1페이즈 | 2페이즈 |
| --- | ---: | ---: |
| 한 번의 잠항에서 사용하는 외부 패턴 수 | `1` | `2` |
| 외부 패턴 사이 대기 | 사용하지 않음 | `0.18초` |

- 잠항 상태는 정해진 패턴 수를 모두 사용하면 끝난다.
- 1페이즈에서는 외부 패턴 셔플 백에서 하나를 사용하고 바로 진입한다.
- 2페이즈에서는 하이드로펌프와 격류 압착을 각각 한 번씩, 무작위 순서로 사용한다.
- 잠항 중 보스 본체의 스프라이트와 충돌체는 전투 영역 밖에 둔다.
- 공격의 출발 위치는 맵 가장자리 물결·그림자·눈빛으로 표시한다.
- `Health.BeginInvulnerability()`와 `EndInvulnerability()`를 짝지어 사용하고 상태 전환이나 사망으로
  무적 잠금이 중복되어 영구 무적이 되지 않게 한다.

### 3.5 진입과 이탈

- 이탈 시간 기본값: `0.34초`
- 진입 시간 기본값: `0.42초`
- 이탈 중에는 큰 물보라를 남기고 바깥쪽으로 잠수한다.
- 진입 위치는 원형 물결로 먼저 표시하며 플레이어와 직접 겹치는 위치를 선택하지 않는다.
- 진입 중에는 보스 충돌체와 접촉 피해를 끈다.
- 노출 위치는 기본적으로 전투장 중앙을 사용한다. 패턴 가독성이 검증되기 전에는 무작위 위치로
  바꾸지 않는다.

## 4. 상시 경기장 기믹: 삼중 해류

삼중 해류는 네 공격 패턴과 별개로 전투 내내 작동하는 경기장 규칙이다. 해류 자체는 피해를 주지
않으며 플레이어의 X축 이동에만 힘을 더한다.

### 4.1 수로 구분

권장 전투 영역의 Y축 `-4.2 ~ 4.2`를 같은 높이의 세 구역으로 나눈다.

| 수로 | 대략적인 Y 범위 |
| --- | --- |
| 아래 | `-4.2 ~ -1.4` |
| 가운데 | `-1.4 ~ 1.4` |
| 위 | `1.4 ~ 4.2` |

경계값은 `arenaHalfSize.y`에서 계산하고 코드에 직접 고정하지 않는다. 플레이어 중심이 들어 있는
수로의 해류 하나만 적용한다.

### 4.2 방향 선택

- 세 수로는 각각 독립적으로 `왼쪽` 또는 `오른쪽`을 뽑는다.
- `좌좌좌`, `좌좌우`, `좌우좌`, `좌우우`, `우좌좌`, `우좌우`, `우우좌`, `우우우` 여덟 조합을
  모두 허용한다.
- 특정 교차 조합만 나오도록 강제하지 않는다.
- 방향 변경 때 새 조합이 이전 조합과 완전히 같으면 다시 뽑는다. 여러 번 같은 결과가 나오면
  무한 반복하지 말고 임의의 한 수로를 뒤집어 최소 한 곳은 변하게 한다.
- 각 조합의 방향은 서로 독립적인 50% 확률로 뽑는다.

### 4.3 기본 수치

| 항목 | 1페이즈 | 2페이즈 |
| --- | ---: | ---: |
| 해류 속도 | `1.45` | `1.60` |
| 방향 유지 최소 시간 | `2.8초` | `2.0초` |
| 방향 유지 최대 시간 | `4.0초` | `3.0초` |
| 변경 예고 | `0.60초` | `0.50초` |

플레이어는 공격 중 실질 이동 속도가 약 `2.5`이므로 해류는 공격하는 동안 크게 느껴진다. 더 올릴
때는 방향 유지 시간이 함께 짧아져 있는지 확인한다 — 둘을 동시에 밀면 조작감이 무너진다.

### 4.4 표현과 물리 규칙

- 각 수로 바닥에 현재 방향을 가리키는 반복 화살표를 표시한다.
- 화살표는 그 수로의 **한가운데 높이**에 띄운다(`WaterCurrentField.LaneCenterY`). 경계선에 붙여
  그리면 어느 수로의 방향인지 헷갈린다.
- 바닥이 옅은 물빛이라 화살표도 옅으면 묻힌다. 짙은 남색 계열로 진하게 그린다.
- 방향 변경 예고 중에는 화살표를 예고 시간에 걸쳐 **천천히 돌린다**. 예전 방향과 새 방향을
  번갈아 점멸시키지 않는다 — 초당 몇 번씩 홱홱 뒤집혀 읽히지 않고 화면만 어지럽다. 도는 것이
  곧 예고이고, 다 돌아간 방향이 곧 새 방향이다. 방향이 그대로인 수로의 화살표는 돌지 않는다.
- 예고가 끝나는 한 프레임에 세 수로 방향을 함께 확정한다.
- 해류는 플레이어에게만 적용한다.
- 갸라도스, 잉어킹, 하이드로펌프, 예고 표시, 범람 영역은 해류의 물리 이동 영향을 받지 않는다.
- 하이드로펌프 경로는 해류 방향과 무관하다. 발사 중에도 해류 방향 변경 예고와 확정을 평소대로
  진행한다.
- 해류 때문에 플레이어가 벽이나 잉어킹을 통과해서는 안 된다.
- 플레이어 이동 속도를 직접 덮어쓰지 말고 기존 입력 이동에 외부 속도 또는 물리 변위를 더한다.
- `Update`에서 트랜스폼을 순간이동시키지 말고 물리 갱신과 충돌을 존중한다.
- 페이즈 전환 중에도 해류는 멈추지 않는다. 보스 사망과 방 이탈 때만 제거한다.

## 5. 잠항 패턴 1: 반사 하이드로펌프

갸라도스가 외곽 깊은 바다의 네 방향 중 한 곳에서 굵은 물대포를 발사한다. 물대포는 전투장 벽에
닿으면 입사각과 같은 각도로 반사된다. 플레이어에게는 **최초 발사 방향만** 예고하고 반사 이후의
경로는 미리 표시하지 않는다.

삼중 해류는 이 패턴 중에도 계속 플레이어를 민다. 물대포 경로는 해류와 무관하므로 방향 변경을
기다리거나 잠그지 않는다.

### 5.1 패턴 순서

1. `Top/Bottom/Left/Right` 네 발사 면 중 하나를 같은 확률로 고른다.
2. 선택한 외곽 원점에 갸라도스의 그림자·눈빛·큰 물결을 표시한다.
3. 예고 시작 시점의 플레이어 위치를 향해 최초 방향을 계산하고 고정한다.
4. 아래 5.3절에 따라 전체 반사 경로를 미리 계산한다.
5. 원점부터 첫 번째 반사 지점까지의 직선만 붉은 예고선으로 표시한다.
6. 예고가 끝나는 순간 계산된 구간 **전체**를 한꺼번에 번쩍이며 발사한다. 선두가 훑어 가지 않는다.
7. 모든 반사점에 동시에 물보라를 표시한다.
8. 번쩍인 경로는 잔류 시간 동안 옅어지며 남고, 그동안 계속 피해 판정을 유지한다.
9. 잔류 판정까지 모두 사라진 뒤 후딜을 적용하고 패턴을 끝낸다.

### 5.2 발사 원점과 최초 진입

- 위·아래는 기존 `HydroOrigin_Top/Bottom`을 사용한다.
- 왼쪽·오른쪽은 새 `HydroOrigin_Left/Right`를 사용한다.
- 발사 원점은 `HydroReflectBounds` 바깥에 있으며 최초 방향은 반드시 전투장 안쪽을 향해야 한다.
- 경로 계산에서 원점 쪽 벽을 처음 통과하는 것은 **진입**이지 반사가 아니다.
- 원점에서 선택한 면과 만나는 진입점을 구하고, 그 점에서 진행 방향으로 작은 여유값을 더한 위치부터
  첫 반사 벽을 찾는다.
- 실제 첫 렌더링 구간은 외곽 원점부터 첫 반사 지점까지 이어 그려 진입점에 시각적 틈이 없어야 한다.
- 최초 방향이 선택한 면의 바깥쪽을 향하거나 모서리를 스치기만 하는 후보는 버린다.

### 5.3 반사 계산

반사 경계는 장식 콜라이더를 레이캐스트해 찾지 않고 축 정렬된 `HydroReflectBounds`의 네 면을 사용한다.
잉어킹, 플레이어, 범람, 출구 문과 다른 콜라이더가 경로를 바꾸면 안 된다.

방향 벡터 `d`와 충돌한 벽의 안쪽 법선 `n`으로 새 방향을 계산한다.

```text
reflectedDirection = d - 2 * dot(d, n) * n
```

- 위·아래 벽에 닿으면 Y 성분의 부호만 바뀐다.
- 왼쪽·오른쪽 벽에 닿으면 X 성분의 부호만 바뀐다.
- 한 번 정한 최초 방향은 이후 플레이어를 추적하지 않는다.
- 반사점에서 새 방향으로 `epsilon`만큼 이동한 위치를 다음 구간 시작점으로 사용한다.
- 모서리 두 면에 동시에 닿는 경로는 허용하지 않는다.
- 반사점은 각 모서리에서 최소 `0.60 unit` 떨어져야 한다.
- 연속된 두 반사점 사이가 `1.00 unit`보다 짧은 경로는 버린다.
- 필요한 반사 횟수를 채우기 전에 유효한 다음 벽을 찾지 못하면 그 후보를 버린다.

반사 횟수는 물줄기의 방향이 실제로 바뀐 횟수다.

- 1페이즈: 첫 번째 벽에서 1회 반사한 뒤 다음 벽에서 종료
- 2페이즈: 첫째·둘째 벽에서 2회 반사한 뒤 세 번째 벽에서 종료

### 5.4 발사 경로 선정

- 첫 후보는 예고 시작 시점의 플레이어 위치를 겨눈다.
- 경로가 모서리 여유, 최소 구간 길이, 반사 횟수 조건을 만족하는지 발사 전에 전부 시뮬레이션한다.
- 실패하면 플레이어 조준점에서 전투장 중심 쪽으로 보정을 늘려 가며 다시 계산한다.
- `hydroAimAttempts` 횟수 안에 성공하지 못하면 선택한 발사 면의 중앙에서 전투장 중심 쪽으로 향하는
  사전에 검증된 예비 각도를 사용한다.
- 예비 각도조차 유효하지 않으면 피해 없는 경고만 남기지 말고 패턴을 취소하고 짧은 후딜 뒤 다음
  상태로 진행한다. 무한 재시도하지 않는다.
- 네 발사 면에서 유효 후보가 나오는지 시작 시 또는 개발 검증에서 확인한다.
- 잉어킹과 플레이어는 경로 계산을 바꾸지 않으며 물대포는 이들을 관통한다.

### 5.5 기본 수치

| 항목 | 1페이즈 | 2페이즈 |
| --- | ---: | ---: |
| 반사 횟수 | `1` | `2` |
| 첫 방향 예고 | `0.58초` | `0.50초` |
| 발사 방식 | 즉발 — 경로 전체 동시 판정 | 즉발 — 경로 전체 동시 판정 |
| 물줄기 너비 | `0.80` | `0.90` |
| 번쩍임 잔류 | `0.35초` | `0.40초` |
| 피해 | `28` | `32` |
| 패턴 종료 후 대기 | `0.20초` | `0.15초` |
| 모서리 최소 거리 | `0.60` | `0.60` |
| 구간 최소 길이 | `1.00` | `1.00` |

즉발이므로 **예고 시간이 이 패턴의 유일한 회피 여유다.** 물줄기가 날아오는 것을 보고 피할 수 없고,
예고선의 각도에서 반사 경로를 미리 읽어 발사 전에 비켜서 있어야 한다. 예고 시간을 줄일 때는 이 점을
반드시 감안한다.

플레이어 공통 무적 시간, 굵기와 판정 일치는 현재 `GyaradosHydroBeam` 구현을 유지한다.
물보라는 수로 경계가 아니라 실제 벽 반사점에서만 생성한다.

### 5.6 1차 구현에서 제거할 동작

- `HydroSettings.refractionStrength`
- 세 수로 방향을 읽어 최초 방향에 수평 성분을 더하는 처리
- 수로 경계 Y와 만나는 교차점을 순서대로 찾는 처리
- 필요한 굴절 횟수를 채우려고 조준 X를 반대편으로 보정하는 처리
- `HydroPumpRoutine`에서 `WaterCurrentField.IsChanging`이 끝나기를 기다리는 처리
- 하이드로펌프 시작·종료 시 `FreezeDirectionChanges()` / `ResumeDirectionChanges()`를 호출하는 처리
- 하이드로 로그의 해류 조합과 수로 경계 교차점 출력

위 항목을 제거하더라도 삼중 해류의 일반 방향 변경과 플레이어 밀기, 범람 감속은 그대로 동작해야 한다.

## 6. 잠항 패턴 2: 격류 압착

전투장 가장자리에서 물이 차오르며 안전한 땅을 사분면 단위로 압축한다. 범람은 추가로 플레이어를
밀지 않는다. 강제 이동은 삼중 해류 하나로 통일한다.

### 6.1 1페이즈

1. 위·아래·왼쪽·오른쪽 중 첫 번째 범람 방향을 무작위로 고른다.
2. 해당 벽에서 거품과 위험 영역을 `0.68초` 동안 예고한다.
3. 물이 해당 축 길이의 `40%`까지 차오르고 피해 영역으로 유지된다.
4. 첫 범람과 수직인 두 방향 중 하나를 무작위로 골라 두 번째 범람을 예고한다.
5. 두 번째 범람이 활성화되면 안전 영역은 한쪽 사분면이 된다.
6. `0.60초` 동안 유지한 뒤 두 범람을 모두 걷어 낸다.

첫 번째가 왼쪽이면 두 번째는 위 또는 아래만 가능하다. 오른쪽을 고르지 않는다.

### 6.2 2페이즈

1페이즈의 두 범람 뒤에 세 번째 범람이 이어진다.

- 세 번째 방향은 첫 번째 방향의 반대편이다.
- 세 번째 예고를 시작할 때 첫 번째 범람을 먼저 걷어 낸다.
- 두 번째 범람은 유지한다.
- 세 번째 범람까지 활성화되면 안전 사분면이 같은 행 또는 열의 반대편으로 이동한다.
- 세 번째 이동은 먼 거리를 요구하므로 예고 시간을 `0.85초`로 둔다.
- 마지막 조합을 `0.50초` 유지한 뒤 모든 범람을 걷어 낸다.

예시:

```text
왼쪽 범람
→ 아래쪽 범람: 오른쪽 위가 안전
→ 왼쪽 물 제거 + 오른쪽 범람: 왼쪽 위가 안전
```

### 6.3 기본 수치

| 항목 | 1페이즈 | 2페이즈 |
| --- | ---: | ---: |
| 범람 깊이 비율 | `40%` | `40%` |
| 첫째·둘째 예고 | `0.68초` | `0.60초` |
| 셋째 예고 | — | `0.85초` |
| 범람 피해 | `28` | `32` |
| 피해 재시도 간격 | `0.60초` | `0.55초` |
| 피격 시 이동 감속 | `25%`, `0.75초` | `30%`, `0.80초` |

- 범람 영역은 실제 피해 사각형과 같은 크기의 진한 위험색으로 표시한다.
- 물이 차오르는 가장자리는 흰 거품선으로 구분한다.
- 범람에 들어가면 즉시 피해를 시도하고, 계속 서 있으면 재시도 간격마다 다시 시도한다.
- 공통 무적 상태에서는 피해를 건너뛰되, 무적이 끝난 뒤에도 안에 있으면 다시 피해를 시도한다.
- 감속은 중첩하지 않고 지속시간만 갱신한다.
- 두 개의 범람만 동시에 활성화될 수 있다.
- 범람이 끝나거나 패턴이 취소되면 감속을 새로 적용하지 않으며 남은 감속은 정상적으로 만료된다.

## 7. 노출 패턴 1: 잉어킹 소환

잉어킹은 플레이어를 돕거나 직접 공격하지 않는다. 해류에도 밀리지 않는 고정 장애물로 남아 이동
경로와 공격 위치를 제한한다.

### 7.1 패턴 순서

1. 기존 소환 패턴에서 살아남은 잉어킹을 모두 제거한다.
2. 후보 위치를 만들고 배치 규칙을 만족하는 지점을 고른다.
3. 각 위치에 **속을 채운 원 + 진한 테두리**를 표시한다. 물빛 바닥 위에서는 가는 테두리 하나만으로는
   눈에 띄지 않아, 어디서 솟아오를지 미리 읽을 수 없다.
4. `0.52초` 뒤 잉어킹이 튀어 올라 고정된다.
5. 마지막 잉어킹이 나타난 뒤 짧은 후딜을 거치고 다음 내부 패턴 선택으로 넘어간다.

### 7.2 기본 수치

| 항목 | 1페이즈 | 2페이즈 |
| --- | ---: | ---: |
| 소환 수 | `3` | `4` |
| 소환 예고 | `0.52초` | `0.45초` |
| 잉어킹 체력 | `70` | `90` |
| 충돌 반지름 권장값 | `0.55` | `0.55` |
| 소환 후 후딜 | `0.20초` | `0.14초` |

### 7.3 잉어킹 규칙

- 잉어킹은 움직이지 않는다.
- 삼중 해류와 범람의 물리 이동 영향을 받지 않는다.
- 플레이어와 단단하게 충돌한다.
- 접촉 피해와 공격 능력이 없다.
- 플레이어의 근거리·원거리·장판 공격으로 피해를 받고 파괴될 수 있다.
- 넉백과 경직에는 면역이다.
- 처치 골드를 주지 않는다.
- `EnemyController`를 사용하지 않으며 `CombatRoomController`의 적 전멸 조건에 포함되지 않는다.
- 다음 잉어킹 소환이 시작되거나 페이즈가 전환되거나 갸라도스가 죽거나 방을 떠날 때 모두 제거한다.
- 소환 직후 갸라도스가 죽어도 잉어킹 때문에 방 클리어가 막히지 않아야 한다.

### 7.4 배치 규칙

- 플레이어 중심에서 최소 `1.25 unit` 떨어진다.
- 갸라도스 중심에서 최소 `1.80 unit` 떨어진다.
- 벽 안쪽 면에서 최소 `0.85 unit` 떨어진다.
- 잉어킹 중심끼리 최소 `1.35 unit` 떨어진다.
- 잉어킹과 벽 사이에 플레이어가 통과할 수 없는 좁은 가짜 통로를 만들지 않는다.
- 세 수로 사이를 이동하는 모든 경계를 동시에 막지 않는다.
- 갸라도스 주변을 완전히 둘러싸지 않는다.
- 조건을 만족하는 위치가 부족하면 소환 수를 줄인다. 잘못된 위치에 억지로 생성하지 않는다.

완전한 연속 좌표 무작위보다 수로 중앙, 수로 경계 부근, 보스 접근 경로 등에 미리 만든 후보점을
섞어 사용하는 것을 권장한다. 후보점 순서를 무작위로 섞은 뒤 위 규칙을 통과하는 점만 채택한다.

## 8. 노출 패턴 2: 똬리치기

갸라도스가 몸을 말고 바깥 고리와 안쪽 원을 차례로 공격한다. 플레이어는 안전하게 멀어질지,
갸라도스 바로 옆에서 계속 공격하다가 두 번째 타격 직전에 빠질지 선택한다.

### 8.1 공격 영역

- `바깥 고리`: 갸라도스 중심에서 안쪽 반지름과 바깥 반지름 사이만 위험하다.
- `안쪽 원`: 갸라도스 중심부터 지정 반지름까지 위험하다.
- 바깥 고리 공격 때 갸라도스 바로 근처와 고리 바깥은 안전하다.
- 두 공격의 예고는 실제 판정과 같은 크기로 표시한다.
- 갸라도스 본체는 패턴 내내 피해를 받을 수 있다.
- 패턴 중 갸라도스는 중앙에서 움직이지 않는다.

### 8.2 1페이즈

순서를 고정해 규칙을 가르친다.

1. 바깥 고리를 `0.65초` 예고한다.
2. 꼬리 휩쓸기 피해를 한 번 적용한다.
3. `0.55초` 뒤 안쪽 원을 `0.40초` 예고한다.
4. 머리 내려찍기 피해를 한 번 적용한다.
5. `0.26초` 후딜 뒤 패턴을 끝낸다.

### 8.3 2페이즈

패턴 시작 시 아래 두 순서 중 하나를 같은 확률로 고른다.

- 바깥 고리 → 안쪽 원
- 안쪽 원 → 바깥 고리

첫 예고가 나타나는 순간 순서를 판별할 수 있어야 한다. 첫 타격 뒤 `0.42초`가 지나면 두 번째 예고를
시작하고, 두 번째 타격 뒤 `0.20초` 후딜을 둔다.

### 8.4 기본 수치

| 항목 | 1페이즈 | 2페이즈 |
| --- | ---: | ---: |
| 바깥 고리 안쪽 반지름 | `1.85` | `1.75` |
| 바깥 고리 바깥 반지름 | `4.50` | `4.70` |
| 안쪽 원 반지름 | `1.85` | `2.05` |
| 첫 예고 | `0.48초` | `0.40초` |
| 두 번째 예고 | `0.40초` | `0.36초` |
| 고리 피해 | `30` | `34` |
| 원 피해 | `32` | `36` |

- 한 번의 고리 또는 원 타격은 플레이어에게 최대 한 번만 피해를 준다.
- 첫 타격과 두 번째 타격의 간격은 플레이어 무적 시간 `0.5초`를 고려한다. 두 번째 판정이 첫 피격의
  무적 시간에 전부 사라지지 않게 실제 타격 시각을 검증한다.
- 갸라도스의 단단한 충돌체 때문에 안쪽 안전 영역이 실제로 지나치게 좁아지지 않는지 확인한다.
- 고리의 위험 범위는 바깥 반지름을 줄이지 않고 **안쪽 반지름을 키워서** 좁힌다. 전체 크기를 줄이면
  "고리 바깥으로 빠진다"는 선택지가 함께 쉬워지지만, 안쪽을 키우면 붙어서 계속 때리는 쪽만 넉넉해진다.
- 안쪽 반지름은 안쪽 원 반지름을 넘기지 않는다. 넘기면 두 공격 모두에 안전한 띠가 생겨,
  자리를 옮기지 않고 패턴 전체를 흘려보낼 수 있다.
- 해류와 잉어킹 때문에 모든 탈출로가 막힌 상태에서는 패턴을 시작하지 않는다. 배치 검사에 실패하면
  잉어킹 중 갸라도스와 가장 가까운 하나를 제거하고 다시 검사한다.

## 9. 패턴 선택 규칙

### 9.1 외부 패턴

- 하이드로펌프와 격류 압착을 별도의 셔플 백으로 관리한다.
- 1페이즈는 잠항할 때마다 하나만 꺼낸다. 두 패턴을 모두 쓰기 전에는 반복하지 않는다.
- 2페이즈는 한 번의 잠항에서 두 패턴을 모두 사용하되 순서는 무작위다.
- 직전 잠항의 마지막 패턴과 다음 잠항의 첫 패턴이 같으면 순서를 바꾼다.

### 9.2 내부 패턴

- 내부 패턴은 추첨하지 않는다. 규칙 하나로 정한다: **잉어킹 소환은 이탈 직전에만 쓴다.**
- 잉어킹은 갸라도스가 잠항한 뒤에도 남아 하이드로펌프와 범람을 피할 길을 좁히는 장애물이므로,
  노출이 끝나기 직전에 깔아야 제 값을 한다. 노출 중간에 깔면 때리는 동안 치워 버리기만 한다.
- 그래서 똬리치기를 한 번 더 넣을 시간이 남아 있는 동안에는 똬리치기를 쓰고, 그만한 시간이
  남지 않으면 소환으로 마무리한 뒤 곧바로 이탈한다.
- 남은 노출 시간이 소환의 최소 실행 시간보다도 짧으면 새 패턴 없이 이탈한다.

### 9.3 중첩 제한

- 하이드로펌프와 격류 압착은 동시에 실행하지 않는다.
- 잉어킹 소환과 똬리치기는 동시에 시작하지 않는다.
- 하이드로펌프가 끝날 때 남은 물줄기 판정까지 제거된 뒤 다음 외부 패턴을 시작한다.
- 격류 압착의 물이 전부 빠진 뒤 다음 상태로 이동한다.
- 잉어킹은 다음 패턴과 상태까지 남을 수 있다.
- 삼중 해류의 방향 변경은 모든 패턴과 겹칠 수 있다. 이것이 갸라도스 난도의 핵심이다.

## 10. 페이즈 전환

체력이 50% 이하가 되면 전환을 요청한다. 실행 중인 내부 패턴은 정상적으로 끝내되 새 패턴은
선택하지 않는다.

1. 보스를 무적으로 만든다.
2. 똬리치기 판정과 예고를 모두 지운다.
3. 남은 잉어킹을 모두 제거한다.
4. 갸라도스가 포효하며 큰 물결이 전투장 전체로 퍼지는 연출을 `0.8초` 재생한다. 이 물결은 피해가 없다.
5. 해류 방향을 즉시 새로 뽑고 2페이즈 유지 시간 범위를 적용한다.
6. 갸라도스가 잠수해 `Submerged` 상태로 들어간다.
7. 외부 패턴 셔플 백과 내부 패턴 셔플 백을 모두 비운다.

페이즈 전환은 노출 시간에 포함하지 않는다. 2페이즈는 외부 패턴 두 개를 수행한 뒤 첫 노출 상태로
들어간다. 전환 중에도 플레이어 이동과 삼중 해류는 계속 작동한다.

## 11. 기본 능력치 권장값

아래 값은 구현 시작점이며 플레이테스트로 조정한다. 갸라도스는 무적 구간 때문에 같은 체력의 상시
노출 보스보다 실전 전투 시간이 길다. 따라서 체력만 지나치게 높여 난도를 만들지 않는다.

| 항목 | 권장값 |
| --- | ---: |
| 최대 체력 | `900` |
| 노출 중 접촉 피해 | `18` / `1.0초` |
| 기본 이동 속도 | `0` — 상태 전환 이동은 전용 로직 사용 |
| 넉백 배율 | `0` |
| 경직 | 면역 |
| 전투 영역 | 반너비 `6.2` × 반높이 `4.2` |

보스의 일반 `EnemyController` 접촉 공격은 노출 상태에서만 허용한다. 잠항·진입·이탈 중에는 접촉
판정과 기본 AI를 모두 끈다.

## 12. 구현 구조 권장안

필수 클래스 이름은 아니지만 책임은 다음처럼 분리한다.

| 책임 | 권장 구성요소 |
| --- | --- |
| 상태 기계, 페이즈, 패턴 선택 | `GyaradosBossController` |
| 수로 표시와 플레이어 해류 | `WaterCurrentField` |
| 진행·벽 반사 물대포 | `GyaradosHydroBeam` |
| 사각 범람 표시와 피해 | `GyaradosFloodZone` |
| 고정 소환물과 파괴 처리 | `MagikarpObstacle` |

잉어킹은 이벤트방 오브젝트를 직접 복제하지 말고 위 스프라이트를 사용하는 전투 전용 프리팹을 만든다.
이벤트 선택지, 초상, 유물 지급 구성요소가 보스방에 따라오면 안 된다.

### 12.1 공용 기능 재사용

- `Health.BeginInvulnerability()` / `EndInvulnerability()` — 잠항과 전환 무적
- `AttackTelegraph` — 첫 발사선, 소환 원, 똬리치기 안쪽 원
- `PrimitiveSprites` — 선, 원, 고리, 사각 범람 영역
- `EnemyAnimator.SetActionState()` — 시전 방향 고정이 필요할 때만 사용

기존 `DamageZone`은 원형 고정 장판 전용이므로 범람과 진행형 반사 빔을 억지로 넣지 않는다. 실제
모양과 판정이 일치하는 전용 구성요소를 만든다.

### 12.2 공격 오브젝트 생명주기

- 공격 오브젝트는 씬 루트의 `Gyarados_Attacks` 아래에 둔다.
- 갸라도스 스케일이나 위치를 바꿔도 공격 오브젝트가 같이 확대·이동하지 않아야 한다.
- 패턴 코루틴은 `attackGeneration` 같은 세대 번호를 확인한다.
- 상태 전환, 페이즈 전환, 사망, 비활성화, 방 이탈 때 세대를 올리고 예약된 공격을 무효화한다.
- `OnDisable`과 `OnDestroy`에서 해류, 플레이어 감속, 충돌 무시, 무적 잠금 등을 원상 복구한다.
- 갸라도스가 죽은 뒤 남은 범람·물대포·잉어킹이 플레이어를 공격하거나 방 클리어를 막지 않아야 한다.

### 12.3 1차 구현 마이그레이션

기존 직렬화 값과 프리팹 참조를 불필요하게 깨뜨리지 않도록 다음 순서로 수정한다.

1. `HydroSettings.refractions`를 `reflections`로 이름을 바꾸고
   `[FormerlySerializedAs("refractions")]`를 붙여 프리팹의 `1`, `2` 값을 보존한다.
2. 더 이상 쓰지 않는 `refractionStrength`와 각 페이즈 초기값을 제거한다.
3. `RefractionEpsilon`은 역할에 맞게 `ReflectionEpsilon`으로 이름을 바꾸되 기존 `0.03` 값을 유지한다.
4. `hydroOriginLeft`, `hydroOriginRight`, `hydroReflectBounds` 참조를 추가한다. 좌우 원점이 비어 있을 때만
   경계 바깥 자동 계산을 사용하고 경고 로그를 한 번 남긴다.
5. `HydroOrigin(bool fromTop)`을 네 면을 표현하는 enum 기반 선택 함수로 교체한다.
6. `PlanHydroPath`에서 수로 번호, 수로 부호, 위·아래 여부를 제거하고 선택 면, 반사 경계, 반사 횟수를
   전달한다.
7. `GyaradosHydroBeam.BuildPath`는 5.2~5.4절의 진입·벽 교차·반사 계산으로 교체한다. 기존 `Segment`,
   `Launch`, 선두 전진, 잔류 구간, 피해와 제거 로직은 유지한다.
8. 하이드로펌프에서 더는 호출하지 않는 `WaterCurrentField.FreezeDirectionChanges()`와
   `ResumeDirectionChanges()` 및 전용 잠금 카운터는 다른 호출처가 없는지 확인한 뒤 제거한다.
   `IsChanging`은 해류 자체의 예고 표시에서 계속 사용하므로 제거하지 않는다.
9. `F3Room7_Boss.prefab`에는 `HydroOrigin_Left/Right`와 `HydroReflectBounds`만 추가·연결한다. 기존 맵,
   보스 앵커, 위·아래 원점과 다른 패턴 값은 재구성하지 않는다.

`FormerlySerializedAs`에는 `UnityEngine.Serialization`을 사용한다. 작업 후 프리팹의 두 페이즈 반사 횟수와
기존 피해·속도·너비·잔류 시간·후딜 값이 유지됐는지 Inspector 또는 프리팹 diff로 확인한다.

### 12.4 반사 경로 계산 책임

경로는 예고 시작 시 한 번 계산해 `Segment` 목록으로 저장한다. 계산 함수는 렌더링이나 코루틴을 직접
시작하지 않는 순수 함수로 두어 네 발사 면과 모서리 사례를 독립적으로 검증할 수 있게 한다.

- 입력: 외곽 원점, 최초 방향, `HydroReflectBounds`, 목표 반사 횟수, `epsilon`, 모서리 여유, 최소 구간 길이
- 출력: 외곽 원점부터 마지막 종료 벽까지의 구간 목록과 각 반사점, 또는 유효 경로가 없을 때 `null`
- 진입면: 선택한 발사 면과 일치해야 하며 반사 횟수에 포함하지 않는다.
- 다음 벽: 양의 거리 중 가장 가까운 한 면만 선택한다.
- 모서리: 두 면까지의 거리가 허용 오차 안에서 같으면 실패 처리한다.
- 종료: 목표 반사 횟수를 채운 뒤 다음 벽에 닿는 구간까지 포함한다.

예고에는 결과의 첫 구간만 사용한다. 실패하면 5.4절의 후보 보정과 예비 각도를 사용하며, 기존
진행형 물줄기는 유효한 목록을 받은 경우에만 발사한다.

## 13. 가독성과 공정성 하한

이 보스는 매우 어려워도 되지만, 무작위 결과 때문에 피할 수 없는 상황을 만들어서는 안 된다.

- 해류 방향 변경은 반드시 먼저 예고한다.
- 하이드로펌프는 반사 이후 경로를 숨기되 첫 방향, 시각적으로 닿는 벽, 진행하는 물줄기와 반사 물보라는
  보여 준다.
- 벽에 닿기 전 허공에서 꺾이거나, 벽 안으로 깊게 들어간 뒤 꺾이거나, 모서리에서 두 번 반사하면 안 된다.
- 하이드로펌프 중에도 해류 방향은 평소대로 바뀔 수 있으며, 해류 변화가 이미 계산된 물대포 경로를
  바꾸면 안 된다.
- 범람은 위험 영역 전체를 활성화 전에 표시한다.
- 잉어킹은 생성 전에 위치를 표시하며 플레이어 위에 즉시 생성하지 않는다.
- 똬리치기는 첫 공격과 두 번째 공격을 서로 다른 예고 모양으로 구분한다.
- 안전 통로 권장 최소 폭은 `1.25 unit`이다.
- 해류 방향 변경과 직접 공격 발동이 같은 프레임에 일어나도 각각의 예고 시간은 줄어들지 않는다.
- 플레이어가 공격 중 이동 속도가 감소한다는 점을 포함해 이동 가능성을 검증한다.
- 난도를 올릴 때 피해, 체력, 해류 속도보다 패턴 순서와 공간 변화부터 조정한다.

## 14. 디버그 로그와 검증 기준

`GyaradosBossController.logPatterns`가 켜져 있을 때 다음을 기록한다.

- 상태 진입과 종료, 남은 노출 시간
- 현재 페이즈
- 세 수로의 이전 방향과 새 방향
- 선택한 패턴과 셔플 백 상태
- 하이드로펌프 발사 면과 원점, 첫 방향, 진입점, 반사점 목록, 반사 횟수, 후보 재시도 횟수
- 범람 방향 순서
- 잉어킹 후보 수, 실제 생성 수, 배치 거부 이유
- 페이즈 전환 요청과 실제 실행 시점

구현 완료 기준:

1. 잠항·진입·이탈 중 어떤 공격으로도 갸라도스 체력이 줄지 않는다.
2. 노출 상태에서는 근거리·원거리·장판 공격이 모두 정상적으로 피해를 준다.
3. 노출 시간이 받은 피해량에 따라 짧아지지 않는다.
4. 1페이즈 잠항은 외부 패턴 1회, 2페이즈 잠항은 서로 다른 외부 패턴 2회 뒤 끝난다.
5. 삼중 해류에서 여덟 방향 조합이 모두 나올 수 있고, 방향 변경마다 최소 한 수로가 바뀐다.
6. 해류가 잉어킹과 갸라도스에는 적용되지 않고 플레이어 충돌을 뚫지 않는다.
7. 하이드로펌프 예고에는 첫 구간만 보이며 1페이즈 1회, 2페이즈 2회 정확히 반사한다.
8. 위·아래·왼쪽·오른쪽 네 발사 면이 모두 선택될 수 있고, 최초 진입면 통과는 반사로 세지 않는다.
9. 각 반사점이 시각적인 벽 안쪽 면과 일치하고 모서리에서 이중 반사하거나 같은 벽에 붙어 떨지 않는다.
10. 하이드로펌프 중 해류 방향 변경이 정상적으로 예고·확정되며 물대포 경로는 그 영향을 받지 않는다.
11. 기존 하이드로펌프의 속도, 너비, 피해, 잔류 시간과 플레이어 공통 무적 시간 적용이 유지된다.
12. 기존 굴절용 `refractionStrength`, 수로 부호·경계 의존성, 해류 잠금 호출이 남아 있지 않는다.
13. 격류 압착은 동시에 최대 두 범람만 유지하며 2페이즈 세 번째 이동에도 도달 가능한 안전 영역이 있다.
14. 잉어킹은 플레이어를 막지만 공격하거나 골드를 주거나 방 클리어 조건에 포함되지 않는다.
15. 잉어킹 배치가 벽·보스·플레이어와 겹치지 않고 모든 수로 경계를 동시에 봉쇄하지 않는다.
16. 똬리치기의 예고 모양과 실제 원·고리 판정이 일치한다.
17. 페이즈 전환, 보스 사망, 방 이탈 후 공격 오브젝트와 코루틴이 남지 않는다.
18. 보스가 죽은 프레임에 플레이어도 맞았을 때 기존 사망·클리어 우선순위가 깨지지 않는다.
19. 최소 20회의 상태 순환을 자동 또는 플레이 모드로 반복해 무한 무적, 패턴 정지, 공격 오브젝트
    누적, 갇힘이 발생하지 않는다.
20. `F3Room7_Boss` 중앙의 플레이 가능 크기는 유지하면서 외곽 깊은 바다와 모든 맵 기준점이 존재한다.
21. 플레이어는 외곽 깊은 바다로 나갈 수 없고, 네 하이드로펌프 원점과 갸라도스의 잠항 표시는
    카메라 안에서 식별할 수 있다.
22. 별도의 수문 스프라이트 없이 기존 바다·모래·암초 타일과 도형 연출만으로 수로 경계, 해류 방향,
    잠항 위치를 구분할 수 있다.
