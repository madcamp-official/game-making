# 코뿌리 보스 구현 명세

> 대상: `F2Room7_Boss`의 `Boss_Rhydon` — 2층 보스
> 구현: `Assets/Game/Scripts/Combat/Bosses/RhydonBossController.cs`
> 기준 단위: Unity 월드 단위. 타일 1칸과 플레이어 폭이 각각 약 `1 unit`이다.

## 0. 핵심 요구사항

- 패턴은 정확히 3종: `스톤샤워`, `뿔드릴`, `이판사판`.
- **세 패턴 모두 근접 공격이다. 투사체를 하나도 쓰지 않는다.**
- 체력 50%에서 2페이즈로 넘어가고, 새 패턴 없이 같은 셋의 강화형만 쓴다.
- 난도는 버터플의 2배 이상.

버터플과 정반대의 보스다. 버터플은 거리를 벌리고 탄을 뿌리지만, 코뿌리는 몸이 닿는 거리에서만
위험하다. 그래서 압박이 "탄을 피해라"가 아니라 "어디에 서 있을 것이냐"로 온다.

> 2026-07-28 재조정: 스톤샤워를 방 전체로 바꾸고, 1페이즈를 옛 2페이즈 수준으로 올렸으며,
> 2페이즈를 그보다 더 올렸다. 이동·예고·후딜·패턴 간격도 전반적으로 짧아졌다.
> 이판사판만 횟수를 따로 정했다 (1페이즈 3회 / 2페이즈 4회).
>
> 2026-07-28 2차 패치: 이판사판이 플레이어를 뚫고 지나가게 했고, 스톤샤워는 예고를 1.5배로
> 늘린 대신 돌이 커지고 많아졌으며 플레이어 주변에도 흩뿌린다.

## 1. 기본 수치

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 최대 체력 | `700` | 버터플 240의 2.9배 |
| 걷기 속도 | `4.2` | 플레이어는 5. 조금 느린 대신 돌진이 아주 빠르다 |
| 접촉 피해 | **`0` (없음)** | 잡몹과 같은 규칙 — 피해는 예고가 보이는 기술에만 있다 |
| 전투 영역 | 반너비 `7` × 반높이 `5` | 벽 안쪽 면과 같다. 벽 콜라이더 중심이 ±7.25·±5.25, 두께 0.5 |
| 몸 여유 (`bodyMargin`) | `0.5` | 이동·돌진 도착점에만 뺀다. 돌 낙하 지점은 벽까지 꽉 채운다 |
| 넉백 | 면역 (`knockbackMultiplier = 0`) | 패턴 위치가 무너지면 안 된다 |

`EnemyController`의 기본 추적 AI는 꺼 둔다(`basicAIEnabled = 0`). 이 컨트롤러가 직접 Rigidbody를
움직이므로, 둘이 동시에 속도를 쓰면 서로 덮어쓴다.

패턴 선택은 버터플과 같은 셔플 백이다. 세 패턴을 한 번씩 다 쓰기 전에는 같은 패턴이 다시 나오지
않고, 백을 다시 채울 때 직전 패턴이 맨 앞이면 뒤로 민다.

패턴 사이 대기는 1페이즈 `0.45`초, 2페이즈 `0.32`초다.

예고 시간에는 절대 하한이 있다 — 차지 `0.30`, 낙하 `0.35`, 조준 `0.28`. 인스펙터 값이 더 작아도
이 아래로는 내려가지 않는다. 2페이즈 값들이 이미 이 선에 거의 붙어 있으므로, 더 줄이려면
하한부터 손대야 한다는 뜻이다.

## 2. 스톤샤워

코뿌리가 발을 구르면 **방 전체**에 돌이 떨어진다. 안전 구역이 따로 없어서, 도망칠 곳을 찾는 게
아니라 그림자를 하나씩 읽고 비켜 서야 한다.

예전에는 코뿌리 주변에만 원을 깔았는데, 그러면 "원 밖으로 나가면 끝"이라 답이 하나뿐이었고
그동안 보스를 때릴 수도 없었다. 지금은 코뿌리 옆에 붙어서도 피할 수 있어서, 계속 때릴 것인지
물러설 것인지를 스스로 고르게 된다. 미리 붙지도 않는다 — 어디에 서 있든 상관없기 때문이다.

떨어질 자리는 세 갈래다.

| 갈래 | 비율 | 뜻 |
| --- | --- | --- |
| 플레이어가 선 자리 | `30%` | 제자리 버티기를 막는다 |
| 플레이어 주변 | `45%` | 거리 `0.9`~`3.4`의 고리 안. 도망칠 방향까지 덮는다 |
| 방 전체 무작위 | `25%` | 멀리 떨어져 있어도 안전지대가 없게 한다 |

**주변 낙하가 이 패턴의 핵심이다.** 제자리만 노리면 예고를 보고 앞으로 한 걸음 걷는 것만으로
전부 피해져, 패턴이 사실상 없는 것과 같아진다. 고리 안에서 뽑을 때 거리를 제곱근으로 펴야
바깥쪽이 성기지 않다 — 그냥 뽑으면 안쪽에 몰려 결국 제자리 조준과 같아진다.

각 돌은 그림자가 먼저 뜨고, 낙하 시간 뒤에 착탄한다. 착탄 판정은 `0.22`초만 남아서 지나간 자리는
곧 다시 안전해진다. **낙하 시간이 곧 예고 시간이다** — 그림자가 뜬 순간부터 착탄까지가 피할 시간이다.

| 항목 | 1페이즈 | 2페이즈 |
| --- | --- | --- |
| 발 구르기 | `0.50` | `0.42` |
| 돌 수 | `20` | `30` |
| 투하 간격 | `0.14` | `0.11` |
| 낙하 시간(예고) | `0.75` | `0.60` |
| 후딜 | `0.50` | `0.40` |

돌 하나: 반지름 `0.74`, 피해 `22`.

예고를 1.5배로 늘린 대신 돌을 20% 키우고 수를 늘렸다. 읽을 시간은 넉넉해졌지만 설 자리가
줄었으므로, "반응 속도"가 아니라 "어디로 갈 것이냐"를 묻는 패턴이 된다.

방 전체가 대상이 되면서 "원을 넓히는" 2페이즈 강화는 뜻이 없어졌다. 대신 수를 크게 늘리고
낙하 시간을 더 줄여, 같은 방에서 서 있을 자리가 계속 줄어들게 했다.

## 3. 뿔드릴

짧게 차지한 뒤 거대한 삼각뿔을 창처럼 찌른다. 뻗기 → 유지 → 들어가기의 세 단계이고,
**뻗어 나온 길이만큼만 판정이 있다.** 끝으로 갈수록 좁아지는 삼각형 모양을 그대로 판정하므로,
예고로 그린 삼각형과 실제로 맞는 범위가 정확히 같다.

찌를 때마다 다시 조준한다. 첫 찌르기를 피한 자리에 그대로 서 있으면 두 번째에 맞는다.
찌르면서 몸도 앞으로 밀고 나간다.

시전 전에 `2.4`까지 붙는다 (뿔 길이보다 짧아야 한다). 접근에 쓸 수 있는 시간은 `1.3`초까지다.

| 항목 | 1페이즈 | 2페이즈 |
| --- | --- | --- |
| 차지 시간 | `0.38` | `0.32` |
| 뿔 길이 | `4.5` | `5.4` |
| 뿔 밑변 | `2.4` | `3.0` |
| 찌르는 횟수 | `2` | `3` |
| 전진 거리 | `1.2` | `1.5` |
| 찌르기 간격 | `0.18` | `0.16` |
| 후딜 | `0.50` | `0.40` |

피해 `26`. 한 번의 찌르기에 한 번만 맞는다.

## 4. 이판사판

조준한 방향으로 방 반대편까지 그대로 밀고 나간다. 연속으로 여러 번 하고, 돌진마다 다시 조준한다.

돌진 방향은 시작할 때 고정한다. 매 프레임 목표 쪽으로 다시 겨누면, 프레임이 길어 한 번에 목표를
지나친 순간 뒤로 돌아 제자리에서 앞뒤로 튄다.

돌진 피해는 `OnCollisionStay2D`가 아니라 `TakeDownRoutine`이 직접 낸다. 접촉 피해를 0으로 끈
지금도 돌진은 그대로 아프다 — 코드에 `dashing` 동안 접촉 피해를 건너뛰는 검사가 남아 있는 것은
접촉 피해를 다시 켜더라도 두 번 맞지 않게 하려는 예비 처리다.

**돌진할 때만 플레이어를 뚫고 지나간다.** 몸으로 막히면 "방 반대편까지 밀고 나간다"는 패턴 자체가
성립하지 않고, 앞을 가로막고 서 있는 게 최선의 방어가 돼 버린다. 구현은 `Physics2D.IgnoreCollision`으로
코뿌리와 플레이어의 콜라이더 짝만 껐다 켠다 — 프로젝트에 레이어가 `Default`뿐이라 레이어 마스크로는
벽까지 같이 통과해 버린다. 걸어다닐 때는 평소처럼 부딪힌다.

| 항목 | 1페이즈 | 2페이즈 |
| --- | --- | --- |
| 돌진 횟수 | `3` | `4` |
| 돌진 속도 | `19.5` | `24` |
| 조준 시간 | `0.30` | `0.28` |
| 돌진 간격 | `0.14` | `0.12` |
| 후딜 | `0.55` | `0.45` |

피해 `24`, 들이받는 반지름 `1.05`. 이 패턴만은 미리 붙지 않는다 — 어차피 방 반대편까지 간다.

## 5. 페이즈 전환

체력이 50% 이하가 되면 요청만 기록하고, **실행 중인 패턴은 정상적으로 끝낸 뒤** 전환한다.
전환 중에는 무적이고, 남아 있던 예고·떨어지던 돌·착탄 판정을 전부 지운다. 몸이 커졌다 돌아오고
충격파가 퍼진 뒤 `0.6`초의 인지 시간을 준다.

전환 시 셔플 백을 비워, 강화 패턴을 특정 패턴으로 고정하지 않고 새로 뽑는다.

## 6. 구현 주의점

- **삼각형 스프라이트** — `PrimitiveSprites.Triangle`. 밑변이 -X, 꼭짓점이 +X다. `localScale`을
  (길이, 밑변 너비)로 주면 창끝이 된다. `AttackTelegraph.CreateTriangle`이 예고에 쓴다
- **떨어지는 돌과 뿔은 캐릭터보다 앞에 그린다** (`sortingOrder = 12`). 공중에 있는 것이라 캐릭터(10)
  뒤로 가면 어디에 떨어지는지 안 보인다
- **공격 오브젝트는 씬 루트의 `Rhydon_Attacks` 아래에 만든다.** 보스(1.2배) 아래에 두면 돌과 뿔까지
  같이 커진다. 사망·방 이동 시 통째로 지운다
- **`holdPosition` 플래그로 몸을 붙든다.** 예고·후딜에서는 매 프레임 속도를 0으로 눌러 플레이어와
  부딪혀 밀리지 않게 하고, 접근·전진·돌진에서만 푼다
- **떨어지는 중인 돌은 `attackGeneration`으로 무효화한다.** 페이즈 전환이 돌을 지운 뒤에도 코루틴은
  계속 돌기 때문에, 세대가 바뀌었으면 착탄시키지 않는다 (버터플 독가루와 같은 장치)
- **시전 방향 고정은 반드시 풀어야 한다.** `EnemyAnimator.SetActionState("Idle", 방향)`으로 멈춰 선
  동안에도 플레이어를 보게 하는데, `ClearActionState()`를 빠뜨리면 패턴이 끝난 뒤에도 그 방향으로
  굳은 채 걷는다
- 코뿌리 애니메이터에는 `Idle`/`Walk` 8방향만 있다. `Charge` 시트가 없어 차지는 색으로만 알린다
  (`windupTint`) — `SetActionState`는 없는 상태를 조용히 무시한다
- **2층 바닥이 밝은 모래색이라 예고 색을 골라야 한다.** 처음에 뿔 예고를 노랑(α 0.42), 뿔 자체를
  흰색에 가깝게 뒀더니 화면에서 **아예 보이지 않았다.** 버터플이 초록 바닥에서 겪은 것과 같은 문제라
  같은 규칙(위험 = 진한 빨강)으로 맞췄다: 예고 `(0.85, 0.1, 0.28, 0.62)`, 뿔은 어두운 강철색
  `(0.22, 0.24, 0.3)`. **예고 색을 바꿀 때는 반드시 실제 화면을 찍어 확인할 것**
