# 버터플 보스 구현 명세

## 1. 문서 목적

이 문서는 1층 보스 버터플의 전투 패턴과 구현 요구사항을 정의한다.

구현 에이전트는 이 문서를 버터플 관련 구현의 우선 기준으로 사용한다. `docs/gameplay-spec.md`의 보스 패턴 미정 부분과 충돌할 경우 이 문서를 우선한다.

요구사항의 의미는 다음과 같다.

- **필수**: 초기 구현에 반드시 포함한다.
- **권장**: 구조상 무리가 없다면 포함한다.
- **제외**: 이번 구현 범위에 포함하지 않는다.

모든 거리와 속도는 Unity 월드 유닛 기준이다.

```text
1유닛 ≈ 바닥 타일 1칸 ≈ 플레이어 스프라이트 가로폭
플레이어 실제 충돌 크기 = 약 0.6 × 0.5유닛
플레이어 이동 속도 = 초당 5유닛
```

## 2. 구현 범위

### 필수

- 버터플 전용 보스 제어 로직
- 플레이어와 거리를 유지하는 이동
- 체력에 따른 2페이즈 전환
- 바람탄 패턴
- 독가루 장판 패턴
- 은빛바람 패턴
- 공격 예고 표시
- 공격 후 빈틈
- 같은 패턴 연속 사용 방지
- 보스 사망 시 모든 패턴과 생성 오브젝트 정리
- 기존 보스방 클리어·보상·진화 흐름 유지

### 권장

- 패턴별 색상과 크기 변화
- 페이즈 전환 연출
- 플레이어와 충돌할 때 접촉 피해
- 보스가 벽에 몰렸을 때 중앙 복귀

### 제외

- 수면·중독 등 상태 이상
- 일반 적 소환
- 새 공격 애니메이션 제작
- 외부 그래픽·음원 다운로드
- 보스전 전용 BGM
- 보스 등장 컷신
- 보스 전용 대형 UI 체력바
- 코뿌리와 갸라도스 패턴 변경
- 범용 보스 데이터 시스템의 과도한 설계
- 폰트 관련 파일 및 UI 폰트 변경

초기 그래픽은 단색 또는 기존 스프라이트를 사용한다. 패턴의 가독성과 게임성을 먼저 검증한다.

## 3. 기존 시스템과의 호환 조건

버터플 오브젝트에는 기존 `EnemyController`, `Health`, `Rigidbody2D`, `Collider2D`, `Animator`, `EnemyAnimator`, `HealthBar`가 연결되어 있다.

다음 동작을 깨뜨리면 안 된다.

- `PlayerCombat`이 `EnemyController`를 통해 버터플을 공격할 수 있어야 한다.
- `CombatRoomController`가 버터플 사망을 감지해야 한다.
- 버터플 사망 시 출구가 열려야 한다.
- 보스 보상 유물이 지급되어야 한다.
- 플레이어 진화가 기존 순서대로 실행되어야 한다.
- 일반 적의 기존 이동과 공격은 변경되지 않아야 한다.

`EnemyController`의 기본 추적 AI와 버터플 AI가 동시에 `Rigidbody2D`를 조작하면 안 된다.

필요하다면 `EnemyController`에 기본 AI 활성화 여부를 제어하는 기능을 추가한다. 기본값은 활성화 상태로 두어 일반 적과 다른 보스의 기존 행동을 유지한다.

예시 API:

```csharp
public void SetBasicAIEnabled(bool enabled);
```

버터플 전용 컨트롤러가 활성화될 때만 기본 AI를 비활성화한다.

---

## 4. 전투 목표

버터플은 플레이어에게 다음 전투 규칙을 가르치는 첫 보스다.

- 공격 전 경고 표시를 확인한다.
- 투사체 사이의 빈틈으로 이동한다.
- 장판이 없는 안전 구역을 유지한다.
- 보스의 공격 후 빈틈에 반격한다.

공격 속도와 투사체 수만으로 난이도를 만들지 않는다. 모든 패턴에는 명확한 예고와 회피 가능한 공간이 있어야 한다.

목표 전투 시간은 약 45~60초다.

## 5. 버터플 기본 설정

| 항목 | 초깃값 |
|---|---:|
| 최대 체력 | 240 |
| 이동 속도 | 2.8 |
| 접촉 피해 | 10 |
| 접촉 피해 재발동 간격 | 1초 |
| 선호 최소 거리 | 3.5 |
| 선호 최대 거리 | 5 |
| 패턴 사이 기본 대기 | 1초 |
| 전투 시작 대기 | 1초 |
| 페이즈 전환 체력 | 최대 체력의 50% |

현재 버터플 프리팹의 최대 체력 150은 240으로 변경한다. 최종 수치는 플레이테스트 후 조정할 수 있도록 직렬화된 필드로 둔다.

모든 밸런스 수치는 코드 상수로 고정하지 않고 Inspector에서 조정할 수 있어야 한다.

## 6. 보스 상태

버터플의 행동은 최소한 다음 상태로 구분한다.

```csharp
Intro
Reposition
PatternCooldown
Windup
Executing
Recovery
PhaseTransition
Dead
```

### 상태 규칙

- `Intro`: 전투 시작 후 1초간 대기한다.
- `Reposition`: 공격하기 적당한 거리 또는 위치로 이동한다.
- `PatternCooldown`: 다음 패턴 전 짧게 대기한다.
- `Windup`: 공격을 예고한다. 이동하지 않는다.
- `Executing`: 공격을 생성하거나 실행한다.
- `Recovery`: 플레이어가 공격할 수 있는 빈틈이다.
- `PhaseTransition`: 체력 50%에서 한 번만 실행한다.
- `Dead`: 이동, 패턴 선택, 공격 생성을 모두 중단한다.

한 번에 하나의 상태만 활성화되어야 한다.

보스가 사망하면 실행 중인 코루틴 또는 예약된 공격을 모두 취소한다.

---

## 7. 기본 이동 규칙

버터플은 플레이어를 직접 추격하지 않고 일정 거리를 유지한다.

### 거리별 행동

- 플레이어와 거리가 `5`보다 크면 플레이어 쪽으로 접근한다.
- 거리가 `3.5`보다 작으면 플레이어 반대 방향으로 물러난다.
- 거리가 `3.5~5`이면 플레이어 주변을 좌우로 선회한다.
- 공격의 `Windup`, `Executing`, `Recovery` 상태에서는 이동하지 않는다.
- 한 번의 위치 조정은 최대 1.5초를 넘기지 않는다.

벽이나 장애물 때문에 목표 위치에 도달하지 못하더라도 패턴 실행이 무한히 지연되면 안 된다.

방 중앙은 월드 좌표 `(0, 0)`으로 고정하지 않는다. 버터플 보스방에 직렬화된 `arenaCenter` 또는 동일한 역할의 기준점을 둔다.

---

## 8. 조준 규칙

방향성 공격은 `Windup` 시작 시점의 플레이어 방향을 저장한다.

저장한 방향은 공격이 끝날 때까지 변경하지 않는다. 공격 예고 표시와 실제 공격 방향은 반드시 일치해야 한다.

```text
Windup 시작
→ 플레이어 방향 저장
→ 해당 방향으로 경고 표시
→ 저장된 방향으로 공격
```

예고 중 플레이어를 계속 추적하는 방식은 사용하지 않는다.

## 9. 패턴 1 — 바람탄

### 사용 페이즈

- 1페이즈
- 2페이즈

### 동작 순서

```text
이동 중지
→ 플레이어 방향 저장
→ 부채꼴 공격 방향 표시
→ 0.7초 대기
→ 저장된 방향으로 투사체 발사
→ 0.8초 Recovery
```

### 1페이즈 수치

| 항목 | 값 |
|---|---:|
| 예고 시간 | 0.7초 |
| 투사체 수 | 3 |
| 발사 각도 | -20°, 0°, +20° |
| 투사체 속도 | 6 |
| 투사체 피해 | 10 |
| 투사체 수명 | 3초 |
| 투사체 충돌 반지름 | 약 0.18 |
| 공격 후 빈틈 | 0.8초 |

### 2페이즈 수치

| 항목 | 값 |
|---|---:|
| 투사체 수 | 5 |
| 발사 각도 | -32°, -16°, 0°, +16°, +32° |
| 나머지 수치 | 1페이즈와 동일 |

### 필수 조건

- 투사체는 벽 또는 플레이어와 충돌하면 사라진다.
- 버터플 자신과 다른 적에게 피해를 주면 안 된다.
- 플레이어의 피격 무적 시간을 존중해야 한다.
- 공격 경고 방향과 발사 방향이 일치해야 한다.
- 투사체 사이에는 플레이어 콜라이더가 통과할 수 있는 간격이 있어야 한다.

## 10. 패턴 2 — 독가루 장판

### 사용 페이즈

- 1페이즈
- 2페이즈

### 동작 순서

```text
이동 중지
→ 장판 위치 결정
→ 원형 경고 표시 생성
→ 0.9초 대기
→ 경고 위치에 독가루 장판 생성
→ 장판은 별도로 지속
→ 버터플은 1초 Recovery
```

### 1페이즈 수치

| 항목 | 값 |
|---|---:|
| 장판 수 | 3 |
| 경고 시간 | 0.9초 |
| 장판 반지름 | 0.9 |
| 장판 지속 시간 | 3초 |
| 장판 피해 | 8 |
| 장판별 재피격 간격 | 1초 |
| 공격 후 빈틈 | 1초 |

### 2페이즈 수치

| 항목 | 값 |
|---|---:|
| 장판 수 | 4 |
| 나머지 수치 | 1페이즈와 동일 |

장판 수와 지속 시간을 동시에 강화하지 않는다.

### 배치 규칙

- 첫 번째 장판은 `Windup` 시작 시점의 플레이어 위치에 둔다.
- 나머지 장판은 해당 위치 주변에 배치한다.
- 배치 위치는 공격 실행 전 확정하며 플레이어를 따라가지 않는다.
- 장판 중심은 전투 가능 영역 안으로 제한한다.
- 장판이 방 전체 이동 경로를 막으면 안 된다.
- 장판끼리 일부 겹칠 수 있지만 안전 구역을 반드시 남긴다.
- 출구와 플레이어 시작 위치를 장판으로 완전히 봉쇄하면 안 된다.

### 피해 규칙

- 장판 안에 들어온 즉시 한 번 피해를 줄 수 있다.
- 계속 머무르면 1초 간격으로 다시 피해를 줄 수 있다.
- 프레임마다 피해를 주면 안 된다.
- 서로 다른 장판의 피해가 같은 프레임에 중첩되어 즉사하지 않도록 플레이어 무적 시간을 존중한다.
- 초기 구현에서는 중독 상태를 적용하지 않는다.

## 11. 패턴 3 — 은빛바람

### 사용 페이즈

- 2페이즈 전용

### 동작 순서

```text
방 중앙으로 이동
→ 이동 중지
→ 1초간 바람을 모으는 경고 표시
→ 8방향 1차 발사
→ 0.45초 대기
→ 22.5도 회전한 8방향 2차 발사
→ 1.2초 Recovery
```

### 수치

| 항목 | 값 |
|---|---:|
| 예고 시간 | 1초 |
| 1회 발사 수 | 8 |
| 발사 횟수 | 2 |
| 발사 간격 | 0.45초 |
| 1차 각도 | 0°, 45°, 90° … |
| 2차 각도 | 22.5°, 67.5°, 112.5° … |
| 투사체 속도 | 5 |
| 투사체 피해 | 12 |
| 투사체 수명 | 4초 |
| 투사체 충돌 반지름 | 약 0.18 |
| 공격 후 빈틈 | 1.2초 |

### 필수 조건

- 두 번째 발사는 첫 번째 발사 사이의 빈틈을 향해야 한다.
- 예고 중 버터플은 움직이지 않는다.
- 첫 번째 발사와 두 번째 발사 사이에 추가 조준을 하지 않는다.
- 은빛바람 종료 후 최소 1.2초 동안 다른 공격을 시작하지 않는다.
- 은빛바람을 연속으로 사용할 수 없다.

## 12. 페이즈 구성

### 1페이즈

조건:

```text
체력 100% 초과 불가 ~ 50% 초과
```

사용 패턴:

- 바람탄
- 독가루 장판

규칙:

- 두 패턴을 같은 패턴 연속 사용 금지 조건으로 선택한다.
- 패턴 사이에 1초의 기본 대기 시간을 둔다.
- 패턴 시작 전 필요하면 최대 1.5초간 위치를 조정한다.

### 페이즈 전환

체력이 처음으로 최대 체력의 50% 이하가 되면 전환 요청을 기록한다.

현재 패턴이 실행 중이라면 해당 패턴과 `Recovery`를 정상적으로 끝낸 뒤 전환한다.

동작 순서:

```text
기본 AI 및 패턴 선택 중지
→ 방 중앙으로 이동
→ 1초 동안 색상 또는 크기 변화
→ 피해가 없는 원형 바람 파동 표시
→ 2페이즈 활성화
→ 은빛바람 1회 강제 실행
```

페이즈 전환은 전투당 한 번만 실행한다.

초기 구현에서는 페이즈 전환 중 무적을 적용하지 않는다.

### 2페이즈

조건:

```text
체력 50% 이하
```

사용 패턴:

- 강화 바람탄
- 강화 독가루 장판
- 은빛바람

패턴 선택 가중치 초깃값:

| 패턴 | 가중치 |
|---|---:|
| 바람탄 | 40 |
| 독가루 장판 | 35 |
| 은빛바람 | 25 |

규칙:

- 직전에 사용한 패턴은 후보에서 제외한다.
- 남아 있는 독가루 장판이 2개 이상이면 독가루를 후보에서 제외한다.
- 은빛바람 직후에는 은빛바람을 후보에서 제외한다.
- 패턴 사이 기본 대기 시간을 0.8초로 줄인다.
- 각 패턴 자체의 `Recovery` 시간은 줄이지 않는다.

## 13. 접촉 피해

버터플과 플레이어의 물리 콜라이더가 접촉한 동안 다음 규칙을 적용한다.

| 항목 | 값 |
|---|---:|
| 피해 | 10 |
| 재피격 간격 | 1초 |

접촉 피해는 프레임마다 발생하면 안 된다.

접촉 피해 때문에 패턴 실행이 취소되거나 버터플의 상태가 변경되면 안 된다.

구현 복잡도가 불필요하게 증가하면 접촉 피해는 초기 구현에서 생략할 수 있다. 생략한 경우 Inspector에 기존 공격력이 남아 플레이어에게 예기치 않은 피해를 주지 않도록 기본 AI를 완전히 비활성화한다.

## 14. 피격과 넉백

버터플은 플레이어 공격으로 피해를 받지만, 일반 적처럼 크게 밀려나 패턴 위치가 무너지면 안 된다.

다음 중 하나를 구현한다.

- 보스에게 넉백 면역 적용
- 일반 적보다 낮은 넉백 배율 적용
- `Windup`, `Executing`, `PhaseTransition` 중에만 넉백 무시

권장 방식은 보스 프리팹에 조정 가능한 `knockbackMultiplier`를 두고 초깃값을 `0`으로 설정하는 것이다.

일반 적의 기존 넉백 동작은 변경하지 않는다.

## 15. 임시 시각 표현

외부 에셋 없이 구현할 수 있어야 한다.

### 공통 색상 권장값

| 요소 | 색상 |
|---|---|
| 일반 공격 경고 | 반투명 노란색 |
| 바람탄 | 하늘색 또는 흰색 |
| 독가루 경고 | 반투명 자주색 |
| 활성 독가루 장판 | 진한 반투명 보라색 |
| 은빛바람 경고 | 밝은 청록색 |
| 페이즈 전환 | 흰색 점멸 또는 밝기 증가 |

### 필수 가독성 규칙

- 경고 표시는 실제 피해 범위와 같은 크기를 사용한다.
- 경고 표시는 지형보다 위, 캐릭터보다 아래에 렌더링한다.
- 활성 장판과 경고 장판을 색상 또는 투명도로 구분한다.
- 투사체는 배경 타일과 명확히 구분되어야 한다.
- 공격 예고와 실제 피해 발생 사이에 최소 0.7초를 둔다.

공격 애니메이션이 없으므로 `Windup` 중 버터플의 색상, 크기 또는 점멸을 사용해 공격 준비 상태를 보여준다.

## 16. 생성 오브젝트 생명주기

버터플 컨트롤러는 자신이 생성한 다음 오브젝트를 추적해야 한다.

- 바람탄
- 은빛바람 투사체
- 독가루 경고
- 독가루 장판
- 페이즈 전환 효과

버터플 사망 시:

1. 진행 중인 패턴을 중단한다.
2. 예약된 발사를 취소한다.
3. 남아 있는 공격 경고를 제거한다.
4. 남아 있는 적 투사체를 제거한다.
5. 남아 있는 독가루 장판을 제거한다.
6. 플레이어에게 추가 피해가 발생하지 않도록 한다.
7. 기존 사망·보상·출구·진화 흐름은 그대로 실행한다.

방이 파괴되거나 다음 방으로 이동할 때도 생성 오브젝트가 씬에 남으면 안 된다.

## 17. 권장 파일 구성

구체적인 이름은 프로젝트 관례에 맞춰 조정할 수 있지만, 역할은 분리한다.

```text
Assets/Game/Scripts/Combat/Bosses/
├── ButterfreeBossController.cs
├── EnemyProjectile.cs
├── DamageZone.cs
└── AttackTelegraph.cs
```

필요한 경우:

```text
Assets/Game/Prefabs/Combat/Boss/
├── WindProjectile.prefab
├── PoisonWarning.prefab
├── PoisonZone.prefab
└── RadialWindProjectile.prefab
```

단순한 단색 도형은 코드에서 생성해도 된다. 런타임에 매 공격마다 텍스처와 스프라이트를 새로 만들지 말고 캐시하거나 프리팹을 사용한다.

초기 구현을 위해 별도의 `ScriptableObject` 패턴 데이터 시스템을 만들 필요는 없다. 수치는 `ButterfreeBossController`의 직렬화 필드로 노출한다.

## 18. 수정 대상

  - 보스 넉백 배율을 지원하기 위한 최소 변경

  - 체력 및 패턴 수치 설정

- 보스 공격에 필요한 신규 스크립트와 프리팹

### 수정 금지 또는 범위 밖

- 폰트 관련 파일 전체

- 일반 적의 밸런스
- 기존 방 진행 순서

공유 코드를 수정할 때는 일반 적과 다른 보스의 기존 동작이 동일하게 유지되어야 한다.

## 19. 완료 조건

다음 조건을 모두 만족하면 초기 구현이 완료된 것으로 본다.

### 전투 흐름

- 버터플 보스방 진입 시 출구가 닫혀 있다.
- 버터플이 1초 후 행동을 시작한다.
- 1페이즈에서는 바람탄과 독가루 장판만 사용한다.
- 체력 50% 이하에서 페이즈 전환이 정확히 한 번 발생한다.
- 페이즈 전환 직후 은빛바람을 한 번 사용한다.
- 2페이즈에서는 세 패턴을 모두 사용할 수 있다.
- 같은 패턴을 연속으로 사용하지 않는다.

### 공격 가독성

- 모든 공격은 피해 발생 전에 경고가 보인다.
- 방향성 경고와 실제 발사 방향이 일치한다.
- 독가루 경고 위치와 실제 장판 위치가 일치한다.
- 바람탄과 은빛바람 사이로 플레이어가 통과할 수 있다.
- 독가루 장판이 전투 공간 전체를 막지 않는다.

### 기존 시스템 호환

- 좌클릭 근거리 공격으로 버터플을 공격할 수 있다.
- 우클릭 잎날가르기로 버터플을 공격할 수 있다.
- 일반 적의 기존 이동과 공격이 유지된다.
- 버터플 사망 시 모든 보스 공격 오브젝트가 제거된다.
- 버터플 사망 시 보상 유물이 지급된다.
- 출구가 열린다.
- 이상해풀이 정상적으로 진화한다.
- 다음 층으로 정상 이동한다.
- 콘솔에 반복 오류가 발생하지 않는다.

## 20. 플레이테스트 후 조정 순서

밸런스가 맞지 않을 경우 다음 순서로 조정한다.

### 너무 어려운 경우

1. 공격 예고 시간을 늘린다.
2. 패턴 사이 대기 시간을 늘린다.
3. 투사체 속도를 낮춘다.
4. 장판 수 또는 지속 시간을 줄인다.
5. 공격 피해를 낮춘다.
6. 마지막으로 보스 체력을 낮춘다.

### 너무 쉬운 경우

1. 보스 체력을 올린다.
2. 패턴 사이 대기 시간을 줄인다.
3. 2페이즈 패턴 가중치를 조정한다.
4. 투사체 수 또는 장판 수를 늘린다.
5. 마지막으로 공격 피해를 올린다.

공격 피해를 먼저 높여 난이도를 조정하지 않는다. 첫 보스의 난이도는 피해량보다 패턴 조합과 이동 공간 관리로 만든다.
