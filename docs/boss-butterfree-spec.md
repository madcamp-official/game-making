# 버터플 보스 2차 개편 구현 명세

> 상태: 1차 구현 완료 후 진행하는 패턴 강화 명세
> 대상: `Room5_Boss`의 버터플 전투
> 주 독자: 구현을 수행하는 AI 에이전트
> 기준 단위: Unity 월드 단위. 현재 프로젝트에서 타일 1칸과 플레이어 폭은 각각 약 `1 unit`이다.

## 0. 핵심 요구사항

버터플은 페이즈마다 서로 다른 공격을 많이 사용하는 보스가 아니다. 플레이어가 세 가지 규칙을 빠르게 학습하고, 2페이즈에서 같은 세 가지의 강화형에 대응하는 보스로 구현한다.

- 1페이즈 패턴은 정확히 3종이다.
- 2페이즈도 새로운 패턴을 추가하지 않고 같은 3종의 강화형만 사용한다.
- 세 패턴은 `바람탄`, `독가루`, `은빛바람`이다.
- 서로 다른 직접 공격을 동시에 시작하지 않는다. 단, 독가루 장판은 다음 패턴까지 유지될 수 있다.
- 각 패턴 자체의 연속 동작과 위치 판단으로 난도를 만든다.
- 2페이즈에서는 예고 시간과 공격 간격을 일부 줄여도 되지만, 아래의 최소 반응 시간을 지킨다.
- 폰트와 텍스트 렌더링 관련 파일은 수정하지 않는다.

이 문서는 현재 동작 중인 1차 구현을 전제로 하는 변경 명세다. 기존 전투를 모두 새로 만들지 말고 필요한 부분만 확장한다.

## 1. 현재 구현 기준선

현재 버터플은 다음 기능까지 구현되어 있다고 가정한다.

- 최대 체력 `240`
- 이동 속도 `7.5` — **플레이어(5)보다 빠르다.** 붙잡아 두고 때리는 보스가 아니라 예고를
  읽고 그 틈에 때리는 보스라, 느리면 쫓아가 붙기만 해도 되는 상대가 된다
- 접촉 피해 `0`, 넉백 면역, **몸으로 밀 수 없음** (`EnemyController.immovable`)
- 플레이어와 거리를 조절하는 이동 및 재배치
- 체력 50% 기준의 2페이즈
- 1페이즈: 바람탄, 독가루
- 2페이즈: 바람탄, 독가루, 은빛바람
- 예고선과 예고 원, 공격 후딜레이
- 보스 사망, 방 클리어, 보상, 진화 등 기존 보스 공통 흐름
- `attackRoot`를 통한 공격 오브젝트 정리

주요 관련 파일은 다음과 같다.

- `Assets/Game/Scripts/Combat/Bosses/ButterfreeBossController.cs`
- `Assets/Game/Scripts/Combat/Bosses/EnemyProjectile.cs`
- `Assets/Game/Scripts/Combat/Bosses/DamageZone.cs`
- `Assets/Game/Scripts/Combat/Bosses/AttackTelegraph.cs`
- `Assets/Game/Scripts/Combat/Bosses/PrimitiveSprites.cs`
- `Assets/Game/Prefabs/Rooms/Room5_Boss.prefab`

## 2. 이전 명세에서 제거할 내용

이 문서보다 앞선 버터플 개편안에 포함됐던 아래 기능은 구현하지 않는다.

- 공중 가르기
- 꽃가루 핵과 파괴 가능한 오브젝트
- 서로 다른 두 패턴의 동시 조합
- 조합 A~D와 같은 별도 조합 패턴 목록
- 버터플 구현만을 위한 `DamageableTarget` 또는 `IDamageable` 추가

AI 에이전트는 저장소나 대화 기록에서 위 항목을 발견하더라도 이번 작업 범위에 포함하지 않는다.

## 3. 보스 정체성과 다른 보스와의 구분

버터플의 전투 정체성은 다음 세 문장으로 제한한다.

1. 바람탄을 보고 짧게 방향을 전환한다.
2. 독가루를 유도하며 남은 이동 공간을 관리한다.
3. 은빛바람의 회전하는 안전 구역을 따라 이동한다.

| 보스 | 나중에 사용할 핵심 정체성 | 버터플에서 제외할 요소 |
|---|---|---|
| 코뿌리 계열 | 돌진, 벽 충돌, 내려찍기, 바위, 충격파, 근접 압박 | 돌진과 충격파 |
| 갸라도스 계열 | 물결, 넓은 빔, 수로, 지속적인 흐름, 경기장 변화 | 빔과 경기장 변형 |

버터플은 원거리 이동 통제형 보스로 유지한다. 새로운 공격 유형을 계속 추가하는 대신 세 가지 패턴의 완성도를 높인다.

## 4. 전체 전투 구조

### 4.1 페이즈 구성

| 구간 | 사용하는 패턴 | 형태 |
|---|---|---|
| 1페이즈, 체력 `100%~50%` | 바람탄 / 독가루 / 은빛바람 | 기본형 3종 |
| 2페이즈, 체력 `50% 이하` | 바람탄 / 독가루 / 은빛바람 | 같은 패턴의 강화형 3종 |

은빛바람을 1페이즈에도 추가한다. 대신 1페이즈 은빛바람은 넓은 안전 구역과 적은 파동으로 규칙을 가르친다.

### 4.2 패턴 선택

- 각 페이즈는 세 패턴을 셔플 백 방식으로 선택한다.
- 세 패턴을 한 번씩 사용하기 전에는 같은 패턴을 다시 선택하지 않는다.
- 같은 패턴을 연속으로 사용하지 않는다.
- 페이즈 전환 후 셔플 백을 새로 만든다.
- 2페이즈 첫 패턴은 강화 은빛바람으로 고정하지 않는다. 세 패턴 중 무작위로 시작해도 된다.
- 하나의 패턴이 완전히 끝나고 후딜레이에 들어간 뒤 다음 패턴을 선택한다.

### 4.3 직접 공격 중첩 제한

- 바람탄 실행 중 독가루나 은빛바람을 시작하지 않는다.
- 은빛바람 실행 중 바람탄을 추가 발사하지 않는다.
- 독가루 배치와 짧은 후딜레이가 끝나면 장판이 남아 있어도 다음 패턴으로 넘어간다.
- 남은 독 장판은 다음 패턴의 이동 경로만 제한하며 새 탄을 만들지는 않는다.
- 페이즈 전환과 보스 사망 시 남은 장판 및 예약된 장판 생성을 모두 취소한다.

## 5. 공정성과 반응 시간

난도를 높이기 위해 2페이즈의 시간을 줄일 수 있지만 다음 하한을 지킨다.

| 예고 종류 | 허용되는 최소 예고 시간 |
|---|---:|
| 조준 바람탄 | `0.35초` |
| 독 장판 | `0.45초` |
| 은빛바람 첫 안전 구역 | `0.55초` |
| 은빛바람 두 번째 이후 안전 구역 | `0.40초` |

공통 규칙은 다음과 같다.

- 조준 방향과 장판 위치는 해당 예고가 시작될 때 확정한다.
- 예고가 시작된 뒤 플레이어를 계속 추적하지 않는다.
- 위험 표시와 실제 공격 범위가 일치해야 한다.
- 안전 통로의 권장 최소 폭은 `1.25 unit`이다.
- 플레이어를 벽과 장판 사이에 완전히 봉쇄하지 않는다.
- 투사체가 이미 플레이어 바로 앞에 도착한 뒤 다음 예고가 나타나는 구조를 피한다.
- 패턴 사이 대기는 1페이즈 `0.70초`, 2페이즈 `0.56초`를 사용한다.
- 패턴 후딜레이는 대체로 1페이즈 `0.70초`, 2페이즈 `0.60~0.65초`를 사용한다.
- 2페이즈 후딜레이는 어떤 경우에도 `0.55초`보다 짧게 만들지 않는다.

## 6. 패턴 1: 바람탄

바람탄은 여러 번의 부채꼴 공격을 보고 이동 방향을 바꾸는 패턴이다. 한 번에 많은 탄을 뿌리는 대신, 매 발사마다 새로 조준해 연속 판단을 요구한다.

### 6.1 1페이즈 기본형

총 2회의 부채꼴을 발사한다.

#### 첫 번째 발사

- 플레이어 현재 위치를 향해 조준한다.
- 예고 시간 `0.45초`.
- 중심 방향 기준 `-16° / 0° / +16°`로 투사체 3개를 발사한다.
- 탄속 `7.5`, 피해 `10`.

#### 두 번째 발사

- 첫 발사 후 `0.25초`가 지나면 새 조준 예고를 시작한다.
- 첫 번째 방향을 재사용하지 않고 플레이어 현재 위치를 다시 조준한다.
- 예고 시간 `0.40초`.
- 중심 방향 기준 `-24° / -12° / 0° / +12° / +24°`로 투사체 5개를 발사한다.
- 탄속 `7.5`, 피해 `10`.

두 번째 발사 후 `0.70초`의 후딜레이를 적용한다.

### 6.2 2페이즈 강화형

총 3회의 부채꼴을 발사한다.

#### 첫 번째 발사: 현재 위치 조준

- 예고 시간 `0.38초`.
- 중심 기준 `-18° / -9° / 0° / +9° / +18°`로 5개 발사.
- 탄속 `8.0`, 피해 `10`.

#### 두 번째 발사: 이동 방향 예측

- 첫 발사 후 `0.18초` 뒤 새 예고를 시작한다.
- 플레이어의 현재 이동 속도를 이용해 약 `0.30초` 뒤 위치를 예측한다.
- 예측 보정 거리는 최대 `1.5 unit`이다.
- 예고 시간 `0.35초`.
- 중심 기준 `-14° / -7° / 0° / +7° / +14°`로 5개 발사.
- 탄속 `8.0`, 피해 `10`.

#### 세 번째 발사: 바람문

- 두 번째 발사 후 `0.18초` 뒤 새 예고를 시작한다.
- 부채꼴 안에 6개의 후보 발사 방향을 만든다.
- 인접한 후보 2개를 비우고 나머지 4개 방향으로 발사한다.
- 비운 두 방향은 플레이어가 통과할 하나의 문이 된다.
- 예고 시간 `0.38초`.
- 탄속 `8.0`, 피해 `10`.
- 예고선으로 실제 발사 방향과 빈 공간을 구분할 수 있어야 한다.

세 번째 발사 후 `0.60초`의 후딜레이를 적용한다.

### 6.3 바람탄 구현 규칙

- 각 발사의 조준은 해당 발사의 예고 시작 시 별도로 확정한다.
- 예고 중에는 방향을 갱신하지 않는다.
- 두 번째 발사의 예측값은 플레이어가 정지 중이면 현재 위치로 대체한다.
- 플레이어가 첫 회피 방향을 계속 유지하면 두 번째 발사에 맞기 쉬워야 하지만, 방향을 바꾸면 피할 수 있어야 한다.
- 세 번째 바람문의 빈 공간은 플레이어 폭보다 충분히 넓어야 한다.
- 탄속을 `8.5` 이상으로 올릴 때는 플레이어 시작 거리와 예고 가독성을 먼저 확인한다.

## 7. 패턴 2: 독가루

독가루는 플레이어가 지나간 자리를 순서대로 막아 이동 공간을 관리하게 하는 패턴이다. 무작위로 여러 장판을 한꺼번에 생성하지 않는다.

### 7.1 1페이즈 기본형

- 플레이어 위치를 `0.28초` 간격으로 총 4회 기록한다.
- 각 위치에는 즉시 예고 원을 표시한다.
- 예고 원은 생성 후 `0.60초`가 지나면 독 장판으로 활성화된다.
- 장판 반지름 `0.9 unit`.
- 장판 유지 시간 `6.0초`.
- 피해 `8`, 기존 틱 피해 방식을 유지한다.
- 마지막 배치를 마친 뒤 `0.70초` 후딜레이를 적용하고, 장판은 남긴 채 다음 패턴으로 넘어간다.

### 7.2 2페이즈 강화형

- 플레이어 위치를 `0.20초` 간격으로 총 6회 기록한다.
- 예고 원은 생성 후 `0.62초`가 지나면 활성화된다. 이 값은 아래 "앞을 노리는 장판" 규칙의
  하한이기도 하다 — `0.50초`로는 앞을 노린 장판을 달려서 통과할 수 없었다.
- 장판 반지름 `0.95 unit`.
- 장판 유지 시간 `7.5초`.
- 피해 `8`, 기존 틱 피해 방식을 유지한다.
- 4번째 위치는 플레이어 현재 위치가 아니라 현재 이동 방향의 `1.2 unit` 앞을 목표로 한다.
- 5번째와 6번째 위치는 다시 플레이어 현재 위치를 사용한다.
- 마지막 배치를 마친 뒤 `0.60초` 후딜레이를 적용하고, 장판은 다음 패턴 중에도 유지한다.

### 7.3 독가루 배치 규칙

- 새 장판 중심은 직전 장판 중심과 최소 `0.85 unit` 떨어뜨린다.
- 너무 가까우면 플레이어 이동 방향으로 보정한다.
- **보정한 자리가 플레이어보다 앞서면 지금 서 있는 자리까지 당긴다.** 이 보정은 장판이 한
  덩어리로 뭉치는 것을 막으려고 있는 것이지 앞길을 막으라고 있는 것이 아니다. 앞을 노리는
  장판은 아래 규칙을 따르는 단 하나뿐이다.
- 그래서 최소 간격은 **달리는 플레이어가 한 기록 간격 동안 나아가는 거리보다 작아야** 한다.
  크면 보정된 장판이 플레이어를 앞질러 진행 방향에 벽을 세운다.
- 이동 방향도 없거나 안전하게 보정할 수 없으면 해당 장판 생성을 생략한다.

#### 앞을 노리는 장판 (`predictIndex`)

- 앞선 거리는 `predictLead`를 그대로 쓰되, **그대로 달리면 활성화 전에 빠져나갈 수 있는**
  거리로 제한한다: `앞선 거리 + 반지름 + 여유(0.4) ≤ 달리기 속도 × 예고 시간`.
- 달리기 속도는 `PlayerController.RunSpeed`를 읽는다 (유물 배율 포함, 공격 감속 제외).
  `5`로 못박으면 구애스카프 하나에 회피 가능 여부가 뒤집힌다.
- 이 장판은 **최소 간격 규칙에서 빠진다.** 밀어내면 위 거리 보장이 깨진다.
- 이 장판은 **줄의 기준점이 되지 않는다.** 되면 뒤따르는 장판들이 "직전 것과 너무 가깝다"로
  줄줄이 생략되어 정작 지나온 자리가 비어 버린다.
- 장판 중심은 방 경계에서 최소 `0.55 unit` 안쪽으로 보정한다. 여기서 방 경계는 **벽 안쪽 면**
  (`RoomArena.HalfSize` = ±7 · ±5)이고, 보정하는 것은 **중심**이다 — 반지름까지 함께 빼면
  벽에 붙은 띠가 통째로 안전지대가 된다. 장판이 벽에 조금 걸치는 편이 옳다.
- 동시에 활성화하거나 예고 중인 독 장판은 최대 8개다.
- 장판이 전투 가능 영역의 약 55% 이상을 점유하지 않게 한다.
- 장판 사이 또는 장판과 벽 사이에 최소 `1.25 unit`의 통로 하나를 남긴다.
- 보스는 독가루 실행 중 플레이어를 향해 새 투사체를 발사하지 않는다.
- 장판 지속 시간을 늘려 기다리는 시간을 만드는 방식보다 배치 간격과 예측 위치로 난도를 조정한다.

### 7.4 독가루 의도

1페이즈에서는 계속 이동하면 지나간 자리가 막힌다는 규칙을 학습한다. 2페이즈에서는 여섯 번의 연속 배치와 한 번의 앞길 차단을 피하고, 남은 장판을 고려해 다음 패턴의 위치까지 정해야 한다.

## 8. 패턴 3: 은빛바람

은빛바람은 보스 주변에서 원형으로 퍼지는 탄막 속에서 부채꼴 안전 구역을 찾아 이동하는 패턴이다. 탄 개수보다 안전 구역의 회전으로 난도를 만든다.

### 8.1 공통 구성

- 원을 40개의 각도 슬롯으로 나눈다.
- 슬롯 간격은 `9°`다.
- 안전 구역에 포함되는 인접 슬롯에서는 탄을 발사하지 않는다.
- 각 파동 전에 원형 예고와 안전 부채꼴을 표시한다.
- 개별 탄마다 예고선을 생성하지 않는다.
- 한 패턴 안에서 안전 구역은 같은 방향으로만 회전한다.
- 회전 방향은 첫 예고 때 화살표, 회전 효과 또는 색 변화로 보여 준다.

### 8.2 1페이즈 기본형

- 총 2파동.
- 파동마다 인접한 12개 슬롯을 비운다.
- 안전 부채꼴은 약 `108°`다.
- 파동당 투사체 28개, 전체 56개.
- 첫 예고 시간 `0.65초`.
- 두 번째 예고 시간 `0.50초`.
- 파동 간격 `0.50초`.
- 두 번째 안전 구역은 첫 안전 구역에서 `54°` 회전한다.
- 탄속 `5.5`, 피해 `12`, 최대 수명 `4초`.
- 두 번째 파동 후 `0.70초` 후딜레이.

### 8.3 2페이즈 강화형

- 총 3파동.
- 파동마다 인접한 8개 슬롯을 비운다.
- 안전 부채꼴은 약 `72°`다.
- 파동당 투사체 32개, 전체 96개.
- 첫 예고 시간 `0.55초`.
- 두 번째와 세 번째 예고 시간 `0.40초`.
- 파동 간격 `0.40초`.
- 안전 구역은 파동마다 같은 방향으로 `54°` 회전한다.
- 탄속 `6.0`, 피해 `12`, 최대 수명 `4초`.
- 세 번째 파동 후 `0.65초` 후딜레이.

### 8.4 은빛바람 안전 규칙

- 예고된 안전 부채꼴과 실제 빈 슬롯이 정확히 일치해야 한다.
- 파동이 시작된 뒤 안전 구역 위치를 바꾸지 않는다.
- 두 번째 파동부터 예고가 짧아져도 `0.40초`보다 짧게 하지 않는다.
- 안전 구역의 최소 실제 통과 폭은 플레이어 폭의 `1.5배` 이상이어야 한다.
- 이전 파동의 탄이 다음 안전 구역 입구를 완전히 막는 각도와 탄속 조합을 사용하지 않는다.
- 안전 구역 밖의 탄 간격은 방 중앙과 중거리에서 빠져나가기 어렵고, 맵 가장자리에서만 간신히 벌어지도록 유지한다.
- 안전 구역을 무작위로 순간 이동시키지 않는다.
- 2페이즈에서도 파동 수를 3회보다 늘리지 않는다.

## 9. 페이즈 전환

- 현재 실행 중인 패턴이 끝난 뒤 2페이즈로 전환한다.
- 패턴 중간에 체력이 50% 이하가 되어도 현재 패턴의 페이즈 값을 도중에 바꾸지 않는다.
- 전환 루틴 시작부터 2페이즈 진입 유예 시간 종료까지 보스는 무적이다.
- 전환 직전에 활성화된 일반 피격 무적이 끝나더라도 페이즈 전환 무적은 별도로 유지한다.
- 전환 연출 중에는 새 공격 판정을 만들지 않는다.
- 남은 투사체와 장판은 전환 전에 반환하거나 제거한다.
- 전환 후 셔플 백을 초기화하고 세 강화 패턴 중 하나를 선택한다.
- 2페이즈 진입 직후 `0.6초` 동안 공격하지 않아 전환을 인지할 시간을 준다.

## 10. 투사체 성능 요구사항

은빛바람 강화형은 한 번에 총 96발을 순차 발사한다. 발사할 때마다 새 `GameObject`, `Rigidbody2D`, `Collider2D`, 시각 자식을 만들면 프레임 끊김이 생길 수 있으므로 투사체 풀을 사용한다.

### 10.1 `EnemyProjectilePool`

- 보스 전투 시작 시 적 투사체 `128개`를 미리 준비한다.
- 준비 단계에서 필요한 컴포넌트와 시각 자식을 모두 생성한다.
- 전투 중에는 비활성 투사체를 대여해 값만 초기화한다.
- 충돌, 벽 이탈, 경기장 밖 이탈, 수명 종료 시 파괴하지 않고 반환한다.
- 비활성 투사체는 물리 시뮬레이션과 업데이트를 수행하지 않는다.
- 보스 사망과 방 종료 시 활성 투사체를 모두 반환한다.
- 풀이 비었을 때 새 투사체를 즉석 생성하지 않는다.
- 풀 고갈 시 해당 발사를 생략하고 개발 빌드에서 경고를 한 번만 남긴다.

### 10.2 대여 시 초기화 항목

- 위치와 회전
- 이동 방향과 속도
- 피해량
- 충돌 반지름
- 남은 수명
- 색상과 시각 크기
- Rigidbody2D 속도
- Collider2D 활성 상태
- 이전 충돌 또는 피격 기록

### 10.3 오브젝트 상한

| 종류 | 상한 |
|---|---:|
| 적 투사체 전체 동시 활성 | 128 |
| 1페이즈 은빛바람 전체 발사 | 56 |
| 2페이즈 은빛바람 전체 발사 | 96 |
| 독 장판과 예고 원의 합 | 8 |

### 10.4 할당과 탐색 규칙

- 투사체마다 `FindAnyObjectByType`를 호출하지 않는다.
- 발사할 때마다 컴포넌트를 새로 추가하지 않는다.
- 플레이어 참조와 경기장 범위는 보스가 한 번 얻어 재사용한다.
- 반복 발사 경로에서 LINQ와 매 프레임 새 배열 또는 리스트 생성을 피한다.
- 은빛바람은 파동당 원형 예고 1개와 안전 부채꼴 표시 1개만 사용한다.

### 10.5 성능 합격 기준

- 준비 완료 후 투사체 발사 순간에 새 투사체 오브젝트나 컴포넌트를 만들지 않는다.
- 활성 투사체 수는 어떤 상황에서도 128개를 넘지 않는다.
- 강화 은빛바람을 반복해도 눈에 띄는 프레임 끊김이 없어야 한다.
- Unity Profiler에서 반복 발사로 인한 지속적인 프레임당 GC 할당이 발생하지 않는 것을 목표로 한다.
- 세 번 이상 전투를 다시 시작해도 풀 상태와 공격 오브젝트가 누적되지 않는다.

## 13. 완료 조건

### 패턴 구성

- 1페이즈에서 바람탄, 독가루, 은빛바람의 기본형만 사용한다.
- 2페이즈에서 같은 세 패턴의 강화형만 사용한다.
- 네 번째 패턴이나 서로 다른 패턴의 조합이 없다.
- 각 페이즈에서 세 패턴을 한 번씩 보기 전에 패턴이 반복되지 않는다.

### 난도와 공정성

- 강화 바람탄은 3회 조준하며 적어도 한 번의 방향 전환을 요구한다.
- 강화 독가루는 6회 배치 중 한 번 앞길을 막고 다음 패턴까지 남지만 탈출 통로를 남긴다.
- 강화 은빛바람은 3파동 동안 회전하는 안전 구역을 따라가게 한다.
- 모든 공격이 예고 시작 후에는 플레이어를 추적하지 않는다.
- 바람탄 예고는 `0.35초`, 독 장판은 `0.45초`, 은빛바람 후속 예고는 `0.40초`보다 짧지 않다.
- 패턴을 모르면 어렵지만, 규칙을 이해하면 반복해서 피할 수 있어야 한다.
- 피격 시 어떤 예고를 놓쳤는지 플레이어가 설명할 수 있어야 한다.
- 단순한 피해량과 체력 증가만으로 난도를 만들지 않는다.

### 성능과 회귀

- 활성 적 투사체는 128개를 넘지 않는다.
- 강화 은빛바람은 전체 96발을 넘지 않는다.
- 독 장판과 예고 원은 합계 8개를 넘지 않는다.
- 투사체 풀 고갈 시 런타임 생성으로 우회하지 않는다.
- 보스 사망 시 투사체, 장판, 예고와 실행 중인 공격이 모두 정리된다.
- 페이즈 전환 이동, 확대 연출, 바람 파동, 진입 유예 시간 동안 보스 체력이 감소하지 않는다.
- 일반 적과 플레이어 공격 동작은 기존과 동일하다.
- 보스 사망, 방 클리어, 보상, 진화 흐름이 유지된다.
- 폰트 관련 파일에 변경 사항이 없다.

## 14. 플레이 테스트 조정 순서

패턴이 너무 쉽거나 어려울 때 다음 순서로 조정한다.

1. 발사 횟수와 장판 위치 규칙
2. 안전 구역 각도와 바람탄 사이 각도
3. 공격 사이 간격
4. 예고 시간. 단, 최소 반응 시간 이하로 줄이지 않는다.
5. 패턴 후딜레이
6. 탄속
7. 피해량과 보스 체력

플레이 테스트에서는 다음을 확인한다.

- 1페이즈 한 번만 보고 세 패턴의 규칙을 이해할 수 있는가?
- 2페이즈 강화가 새로운 패턴이 아니라 익숙한 패턴의 어려운 버전으로 느껴지는가?
- 바람탄을 피하려면 실제로 방향을 바꿔야 하는가?
- 독가루가 이동 공간을 압박하지만 플레이어를 가두지는 않는가?
- 은빛바람의 회전 방향과 다음 안전 구역을 즉시 읽을 수 있는가?
- 어려운 공격 뒤 최소 한 번 이상 보스를 공격할 시간이 있는가?
- 세 번 연속 전투해도 프레임 저하나 남은 공격 오브젝트가 없는가?
