# 플레이어블 캐릭터 확장 가이드

2026-07-30 기준. 파이리·꼬부기 계열을 실제로 구현하기 전에 캐릭터 선택, 진화, 기술 습득과
강화가 이상해씨 전용 전역 배열에 묶이지 않도록 정리한 구조를 설명한다.

## 현재 상태

- 이상해씨 계열만 완성돼 있다.
- `Charmander.asset`과 `Squirtle.asset`은 선택 화면에 나오지만 `fallbackCharacter`로
  `Bulbasaur.asset`을 가리킨다. 둘 중 하나를 골라도 실제 런과 결과 기록은 이상해씨로 진행된다.
- 미구현 카드에는 선택 화면과 조작 안내에서 `현재 이상해씨로 시작`이라고 표시한다.
- 두 계열의 기술, 능력치, 스프라이트와 전투 효과는 아직 만들지 않았다.

## 데이터 책임

`CharacterData` 하나가 다음을 가진다.

- 선택 화면 이름·플레이 스타일·초상·미리보기 Animator
- `fallbackCharacter`: 미구현 상태에서 대신 플레이할 완성 데이터
- `moveSet`: 네 기술의 슬롯/습득 순서, 이름, 설명, 속성, 강화 후보
- `stages`: 세 진화 단계의 Animator, 초상, 최대 체력, 슬롯별 `movePowers`

`moveSet.moves` 배열 순서는 고정이다.

| 배열 위치 | 입력 | 습득 시점 |
|---|---|---|
| 0 | 좌클릭 | 시작 |
| 1 | 우클릭 | 시작 |
| 2 | Shift | 1차 진화 |
| 3 | Space | 2차 진화 |

`startingMoveCount`를 바꾸면 시작 기술 수를 다르게 만들 수 있지만, 현재 게임 진행은 `2 → 3 → 4`를
전제로 한다. 기술은 최대 네 개, 한 기술의 강화 획득은 최대 두 개다.

## 새 계열을 실제로 연결하는 순서

1. `MoveType` 끝에 신규 기술 ID 네 개를 추가한다. 기존 값 사이에 끼워 넣지 않는다.
2. `MoveUpgradeId` 끝에 강화 ID를 추가하고 `MoveUpgrades.All`에 효과 문구와 수치를 등록한다.
3. `PlayerCombat.TryUseSlot`, `CooldownProgress01`, `SetMovePowers`에 신규 기술 실행·쿨다운·단계 위력
   연결을 추가한다. 입력과 HUD 코드는 수정하지 않는다.
4. 필요한 투사체, 장판, 상태 효과 등 독립 컴포넌트를 구현한다. 기술 강화는
   `PlayerMoves.HasUpgrade` 또는 전용 배율 프로퍼티를 통해 읽는다.
5. 캐릭터 에셋의 `moveSet`에 네 기술과 기술별 강화 ID를 슬롯 순서대로 채운다.
6. 세 진화 단계와 각 단계의 `movePowers` 네 칸을 채운다. 피해가 없는 기술은 0을 쓸 수 있다.
7. 초상, 8방향 Idle/Walk/Attack Animator를 연결한다.
8. 모든 데이터와 실행부가 준비된 뒤 `fallbackCharacter`를 비운다.

## 반드시 확인할 회귀 항목

- 새 런과 같은 캐릭터 재도전에서 배운 기술·강화·쿨다운·장판 상태가 초기화되는가
- 시작 시 기술 두 개만 열리고 두 번의 진화에서 올바른 기술이 하나씩 열리는가
- HUD 이름·입력·속성·쿨다운이 현재 캐릭터의 기술 세트를 따르는가
- 강화 후보에 배우지 않은 기술과 다른 캐릭터의 강화가 섞이지 않는가
- 한 기술을 두 번 강화하면 해당 기술의 나머지 후보가 더 나오지 않는가
- 근접/원거리 유물과 이벤트 배율이 기술 데이터의 `attackKind`를 따르는가
- 단계별 `movePowers`와 진화 후 최대 체력이 올바르게 적용되는가
- 미구현 캐릭터는 이상해씨로 시작하고, 완성 후 폴백을 비우면 자기 데이터로 시작하는가
